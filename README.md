# SkyFlow-Dynamics

**The single source of truth for multirotor UAV dynamics — as math, not as a simulator.**

Every force, torque, and actuator model known to us is captured here **symbolically** (SymPy),
with full provenance, and pinned down by two independent kinds of tests:

- **Accuracy** (`properties/`) — physics invariants that must hold regardless of where the
  equations came from: equilibria, conservation/dissipation, symmetries, exact Jacobians vs
  finite differences, dimensional consistency, closed-form limits.
- **Authenticity** (`golden/`) — frozen `(state, input, params) → derivative/next-state`
  vectors generated by *running the actual reference implementations* (RotorPy
  `research-additions`, Crazyflow, SkyDreamer), stored with commit-level provenance.
  Any future backend, in any framework, is correct iff it reproduces these.

Because the source of truth is symbolic, target frameworks (JAX first) are a **code-generation
step, not a rewrite**: `sympy.lambdify` / printers emit NumPy, JAX, PyTorch, or C from the same
expressions, and every backend runs the same golden + property suite.

## Repository layout

| Path | Contents |
|---|---|
| `spec/` | The SymPy source of truth: one module per physics domain, plus `registry.py` — every term with tier, provenance, and tests. |
| `properties/` | pytest suite of physics invariants (accuracy): symbolic proofs, conservation, symmetry, dimensional scaling, Jacobian-vs-FD, and the golden authenticity tests. |
| `golden/vectors/` | Frozen reference vectors from **three independent provenances**: RotorPy `research-additions` (full model, 12 files), Crazyflow's actual running code, SkyDreamer's actual running code — each with commit/sha provenance. |
| `golden/generate/` | The generator scripts that produced them (rerunnable against the pinned sources). |
| `golden/checkdata/` | Published check data from pinned documents (archaic-source exception): author-run reference statistics where the reference code is no longer executable. Currently NASA CR-1998-206937 (Dryden). |
| `docs/equations.md` | Generated equation catalog (`uv run python tools/render_docs.py`). |
| `REFERENCES.md` | Per-source evaluation ledger — every source ever assessed, including **rejected** models and why. |
| `INTAKE.md` | The protocol for evaluating a new paper/repo against the registry. |
| `backends/` | Generated adapters — `backends/jax.py` (live): the spec emitted to JAX via `sympy.lambdify`, validated by the same golden + property suites (`properties/test_backend_jax.py`). |
| `harness/` | *(later, TBD)* the discrete/stateful simulation layer (command delay lines, ZOH control rates, disturbance resampling, RNG) — deliberately **not** part of the math spec. |

## Canonical conventions

Everything in this repo uses exactly these; converters to other conventions live at the
boundaries (golden generators, future backends).

- **World frame W**: right-handed, `ẑ_W` up. Gravity `g_W = (0, 0, −g)`, `g` a parameter (9.81 by default).
- **Body frame B**: right-handed, `x̂_B` forward, `ŷ_B` left, `ẑ_B` up through the rotor plane.
- **Quaternion** `q = (q_w, q_x, q_y, q_z)` — **scalar-first (wxyz)**, Hamilton product,
  unit norm, representing the body→world rotation: `r_W = R(q) · r_B`.
- **Quaternion kinematics**: `q̇ = ½ · q ⊗ (0, ω_B)` with `ω_B` the body-frame angular rate.
- **Rotor spin sign** `s_i ∈ {+1, −1}`: the sign of rotor *i*'s angular velocity about `+ẑ_B`
  (physical spin). The aerodynamic reaction (yaw) torque on the body is `−s_i · Q_i(Ω_i) · ê_i`
  (it opposes the spin). ⚠ RotorPy's `rotor_directions` encodes the *torque* sign, i.e.
  `rotor_directions = −s`.
- **Units**: SI throughout; angles in rad, rotor speeds in rad/s.
- **State**: `s = (x_W, v_W, q_WB, ω_B, Ω₁…Ω_n)`. Wind velocity, external force (world), and
  external torque (body) are **exogenous inputs**, not state.

## Term tiers

Every term in `spec/registry.py` carries a tier:

- **`verified`** — implemented and cross-validated in a reference simulator; covered by golden
  vectors and property tests here.
- **`candidate`** — credible published model, symbolically checked and cited, awaiting numeric
  validation against a runnable reference.

## JAX backend

`backends/jax.py` is not handwritten physics: every dynamics function is code-generated from
the SymPy spec on first use and pinned by the same golden vectors as the spec itself
(`properties/test_backend_jax.py`). Install with the extra (`uv sync --extra jax`; the dev
group already includes it), then:

```python
import jax, jax.numpy as jnp
from backends import jax as skyflow
from spec.parameters import CRAZYFLIE

p    = skyflow.pack_params(CRAZYFLIE)          # golden-file param dict → flat vector
f    = skyflow.statedot_fn()                   # ṡ = f(s, u, p)   (n=4, first-order motor)
step = skyflow.rk4_step_fn()                   # s⁺ = step(s, u, p, dt), raw integrator
roll = jax.jit(skyflow.make_rollout(step, 0.0, 2500.0))   # lax.scan trajectory

fleet_f = jax.jit(jax.vmap(f, in_axes=(0, None, None)))   # batched vehicles
```

Everything is a pure single-vehicle function over the canonical flat vectors (`state_slices`
/ `input_slices` give the block layout): compose `jax.jit` / `jax.vmap` / `jax.grad`
yourself. Precision follows the ambient JAX config — enable x64 to reproduce the golden
vectors at their 1e-9 tolerances; float32 is the usual RL-rollout choice. The discrete
harness (command delay, control-rate ZOH, disturbance schedules) stays out of the backend
by design; `post_step` / `make_rollout` replicate only the reference post-step the golden
step vectors pin (quaternion renormalization, rotor-speed clipping).

## Regenerating golden vectors

Each generator pins its source (commit hash / file sha256 recorded in the JSON provenance):

```bash
# RotorPy (run from the rotorpy checkout, uses its venv):
cd ../rotorpy && uv run --extra all python \
    ../SkyFlow-Dynamics/golden/generate/gen_rotorpy.py --out ../SkyFlow-Dynamics/golden/vectors

# Crazyflow (bare-package shim over the local fork):
uv run --with scipy --with array-api-compat python golden/generate/gen_crazyflow.py --out golden/vectors

# SkyDreamer (execs their literal dynamics source, njit stubbed):
uv run python golden/generate/gen_skydreamer.py --out golden/vectors

# NASA CR-1998-206937 Dryden check data (pinned document, not runnable code — a
# self-checking transcription freezer; --pdf verifies the sha256 pin if you have the file):
uv run python golden/generate/gen_dryden_cr206937.py
```
