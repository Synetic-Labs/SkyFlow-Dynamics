## JSBSim (JSBSim-Team/jsbsim @ 9a0b028)

JSBSim (master @ commit 9a0b028, all files read locally after fetching from raw.githubusercontent.com/JSBSim-Team/jsbsim) contains two thruster models relevant to quadrotors. FGPropeller is a classic axial advance-ratio model: J = V_a/(nD) using only the shaft-axis velocity component, T = C_T(J)*rho*n^2*D^4, P = C_P(J)*rho*n^3*D^5 with explicit linear rho scaling, windmilling handled implicitly by table sign (no special-case code, RPM floored at 0), momentum-theory induced velocity with a sign-safe branch (McCormick eqn 6.15), P-factor as a thrust acting-point shift, and gyroscopic moment M = omega_i x (I_p*Omega*x_hat) whose sign was historically wrong and is only correct for prop XML version > 1.0 — the spec's -w x h formulation matches the corrected version. FGRotor is a compact SH79 (NASA TP-1285) helicopter model whose highest-value transferable pieces are: (1) Glauert dynamic inflow — dnu/dt = (C_T/(2*sqrt(mu^2+lambda^2)) - nu)/tau with exact exponential discretization and tau = 16/(gamma*Omega) (Gessow/Amer NACA TN-1982), coupled to a Bailey (NACA Rep. 716) closed-form C_T/sigma in lambda, mu, theta_0; (2) body-rate-dependent blade flapping (p/Omega, 16q/(gamma*Omega) terms per NACA TN-2136) producing rotor pitch/roll damping absent from rotorpy's velocity-only kflap term; (3) an in-ground-effect factor scaling induced inflow by 1 - exp(-k*h) (Talbot NASA TM-73254 eqn 10a) — ground effect is a genuine gap in rotorpy's inventory; (4) Bramwell-based torque with (1+4.5*mu^2) forward-flight growth. The propulsion directory also holds FGBrushLessDCMotor, an exact implementation of Drela's QPROP three-constant BLDC model (I = (V - RPM/Kv)/R_m, Q = (I - I0)/Kv) which, combined with FGPropeller's physical shaft ODE I_xx*domega/dt = Q_m - Q_aero, is a mechanistic replacement for the spec's fitted motor-lag/voltage-sag chain and yields per-motor current for battery modeling. Atmosphere: USSA-1976 piecewise-lapse T(h), P(h) via eqns 33a/33b, rho = P/(RT); thrust ~ rho is explicit in both thrusters, and a one-layer version is a cheap, differentiable addition since rotorpy has no density-altitude scaling. JSBSim has no battery model and its plain FGElectric is weaker than the spec's existing electrical modeling; transmission/clutch/freewheel dynamics are irrelevant for direct-drive multirotors. All adopt-candidates carry NACA/NASA/Drela/McCormick/Bramwell provenance and are smooth enough for the planned JAX port (minor patches: sqrt guard at S=0, deadband smoothing, table interpolation).

### Advance-ratio propeller model: C_T(J), C_P(J) tables with explicit rho scaling — **ADOPTED (candidate tier)**

- **Equations:** J = V_a/(n*D) if n > 0.01 rev/s, else J = V_a/D (numerical guard only, dimensionally inconsistent). T = C_T(J) * rho * n^2 * D^4. P_req = C_P(J) * rho * n_eff^3 * D^5 with n_eff = max(n, 0.01). Q_aero = P/omega. Optional multiplicative corrections: C_T *= CtFactor * CT_MACH(M_tip), C_P *= CpFactor * CP_MACH(M_tip), where helical tip Mach M_tip = sqrt(V_tip^2 + V_a^2)/a_sound, V_tip = n*D*pi. Symbols: V_a = axial component of local aerodynamic velocity at the prop hub in the thruster frame [ft/s], computed as the x-component of R^T*(v_aero_body + omega_aero_body x r_hub) (Stevens & Lewis eqn 8.2-1) where R = thruster-to-body rotation, r_hub = hub position from CG [ft]; n = prop speed [rev/s]; D = prop diameter [ft]; rho = air density [slug/ft^3]; T [lbf]; P [ft*lbf/s]. Frame: thruster (shaft) frame, x along thrust axis. Windmilling/reverse flow: no special-case code — the C_T table simply extends to high/negative J where C_T < 0 (drag) and C_P < 0 (windmill drives the shaft, ExcessTorque < 0 decelerates or accelerates the prop); negative V_a gives negative J, covered by the table domain; the only hard guards are RPM >= 0 ("engine won't turn backwards") and the n floors above.
- **Source:** JSBSim master @ commit 9a0b028, src/models/propulsion/FGPropeller.cpp lines 220-249 (J, local velocity, thrust), 307-372 (power), 296 (RPM>=0 clamp), 227-230 (tip Mach); local copies read at /tmp/claude-1000/-home-james-CODE-rotorpy/ad4303ea-217b-4748-a204-8c4eaec759a2/scratchpad/jsbsim/FGPropeller.cpp
- **Parameters:** D [ft], Ixx [slug*ft^2, floor 1e-6], CtFactor = CpFactor = 1.0 default; tables are per-propeller data (JSBSim ships APC-style examples in its prop XML files)
- **Relevance:** This is the standard fixed-pitch propeller parameterization. It generalizes rotorpy's multiplicative atan2 advance-ratio correction: rotorpy's (1 + k_angle*atan2(vz, r*Wbar) + k_hor*atan2(|vxy|, r*Wbar)) is a two-parameter small-perturbation surrogate for C_T variation with inflow, whereas C_T(J)/C_P(J) tables capture the full nonlinear axial-inflow behavior including windmilling, at the cost of needing measured prop data (UIUC/APC databases exist for small UAV props). Note JSBSim uses ONLY the axial velocity component in J — edgewise flow does not enter C_T at all, so rotorpy's k_hor horizontal term has no JSBSim counterpart; the two approaches are complementary.
- **Notes:** Adoption path for a quadrotor: keep rho and n^2 D^4 scaling exact, fit C_T(J), C_P(J) from UIUC prop database for the actual prop instead of the polynomial c0+c1*W+c2*W^2 (which is a fixed-J slice of this model). Table lookup is JAX-friendly via interpolation. The J = V/D fallback at n<0.01 is a hack, not physics — do not copy it literally.

### Momentum-theory induced velocity at the prop disk with sign-safe branch — **ADOPTED (candidate tier)**

- **Equations:** S = V_a*|V_a| + 2T/(rho*A), A = pi*D^2/4 [ft^2]. If S > 0: v_i = 0.5*(-V_a + sqrt(S)); else v_i = 0.5*(-V_a - sqrt(-S)). Symbols: V_a = axial aerodynamic velocity at hub [ft/s] (thruster frame, positive into the disk from front), T = thrust [lbf], rho [slug/ft^3], v_i = induced velocity [ft/s], positive downstream. This is the exact quadratic-root solution of actuator-disk momentum theory T = 2*rho*A*(V_a+v_i)*v_i, written to stay real-valued when V_a and T have opposing signs.
- **Source:** JSBSim master @ 9a0b028, src/models/propulsion/FGPropeller.cpp lines 251-261; code comment cites B. W. McCormick, "Aerodynamics, Aeronautics, and Flight Mechanics", 1st ed., eqn 6.15
- **Parameters:** none beyond D and rho
- **Relevance:** rotorpy's inventory has no induced-velocity state; v_i is the physically correct input for (a) ground-effect models, (b) climb/descent thrust corrections (would replace or justify the k_v2*vz*|vz| term), and (c) downwash-on-airframe effects. Caveat: momentum theory is invalid in the vortex-ring-state band (-2 < V_a/v_h < 0 roughly); JSBSim's sign-branch keeps the math real but does not model VRS thrust fluctuation.
- **Notes:** Cheap, closed-form, differentiable except at S=0 (smooth-min patch trivial in JAX). Credible provenance (McCormick).

### P-factor as thrust acting-point displacement — already covered

- **Equations:** v_t = sqrt(v^2 + w^2) [ft/s] (tangential/in-plane hub velocity, thruster frame); psi = atan2(v_t, V_a + v_i) [rad]; k = Sense * P_Factor * psi / v_t [ft*s]; acting point shift: y_act = y_hub + k*w, z_act = z_hub + k*v (structural frame, inches in JSBSim config). Resulting moments: M_pitch = T*Sense*(z_act - z_hub)/12, M_yaw = T*Sense*(y_act - y_hub)/12 [ft*lbf]. Note the induced velocity v_i in the atan2 denominator attenuates crosswind influence.
- **Source:** JSBSim master @ 9a0b028, src/models/propulsion/FGPropeller.cpp lines 263-278 and 376-385
- **Parameters:** P_Factor: user-supplied scalar > 0 [dimensionless-ish, absorbs blade geometry]
- **Relevance:** This is the asymmetric-disk-loading moment from edgewise inflow. rotorpy already produces the equivalent physical effect via the blade-flapping moment -kflap*W*(v x z) plus per-rotor H-force with w x r lever arm; JSBSim's version is just a different single-parameter lumping. Nothing new to gain for a multirotor.
- **Notes:** Interesting detail worth copying if ever revisited: dividing by (V_a + v_i) instead of V_a to soften the correction at high disk loading.

### Gyroscopic propeller moment H = I_p*Omega, M = omega x H (sign via version attribute) — already covered

- **Equations:** H_prop = (Ixx * omega * Sense * Sense_multiplier, 0, 0) in thruster frame [slug*ft^2*rad/s]; applied body moment vMn = omega_i x (R*H_prop) + R*Q_shaft, where omega_i = in.PQRi = body angular velocity w.r.t. the INERTIAL (ECI) frame expressed in body axes [rad/s] (i.e. includes Earth rotation), R = thruster-to-body rotation matrix, Q_shaft = (-Sense*P_engine/max(0.01, omega), 0, 0) [ft*lbf] is the shaft reaction torque. operator* on two FGColumnVector3 is the cross product (verified in src/math/FGColumnVector3.h lines 180-190). Sign convention: as written this is +omega x H, but for propeller XML files with version > 1.0, Sense_multiplier = -1, making the applied moment effectively -omega x H_actual; FGPropeller.h lines 139-151 state explicitly that the historical (version<=1.0) sign was WRONG and is kept only for backward compatibility.
- **Source:** JSBSim master @ 9a0b028, src/models/propulsion/FGPropeller.cpp lines 73-76 (Sense_multiplier), 280-300 (vH, vTorque, vMn); FGPropeller.h lines 139-151 (sign-bug documentation); FGColumnVector3.h lines 180-190 (cross product)
- **Parameters:** Ixx = propeller + shaft rotational inertia [slug*ft^2]
- **Relevance:** Confirms the spec's existing formulation: rotor-inertia reaction torque plus gyroscopic precession -omega x h is exactly what JSBSim computes for version>1.0 props. The only deltas: JSBSim uses inertial rates PQRi (includes Earth rate — irrelevant at quadrotor scales) and supports a tilted shaft via R (the spec already has per-rotor thrust-axis misalignment).
- **Notes:** The documented historical sign bug is a useful cautionary test case: a sign flip here is hard to notice in hover and only shows up in aggressive yaw+pitch coupling — worth a dedicated unit test in rotorpy (may already exist).

### Physical shaft-speed dynamics from torque balance (instead of pure first-order lag) — **ADOPTED (candidate tier)**

- **Equations:** P_avail = P_engine - P_req(J, n); Q_excess = P_avail/omega (omega floor 0.01 rad/s); d(n)/dt = Q_excess/(2*pi*Ixx); discretized explicit Euler: n_{k+1} = n_k + (Q_excess/Ixx)/(2*pi) * dt, then RPM = 60*n, clamped RPM >= 0. Symbols: P_engine = engine/motor shaft power [ft*lbf/s], P_req = C_P(J)*rho*n^3*D^5 aerodynamic absorbed power, Ixx = rotational inertia [slug*ft^2], n [rev/s]. Equivalent torque form: Ixx*domega/dt = Q_motor - Q_aero(omega, J).
- **Source:** JSBSim master @ 9a0b028, src/models/propulsion/FGPropeller.cpp lines 235, 291-296
- **Parameters:** Ixx per prop [slug*ft^2]
- **Relevance:** The spec currently models motor response phenomenologically (first-order tau_m + asymmetric quadratic spin-up/down + exact-exponential discretization). The torque-balance ODE is the physical mechanism underneath: the effective time constant emerges as tau ~ Ixx*omega/(3*C_P*rho*n^2*D^5) and automatically varies with operating point, load, and air density — the asymmetry the spec hand-codes falls out for free when Q_motor saturates differently up vs down. Combined with the BLDC model (below) it closes the loop V -> I -> Q_m -> omega without fitted lag constants.
- **Notes:** Adopt as an alternative motor backend, not a replacement — the fitted first-order model is cheaper and already validated for rotorpy's props. JSBSim's explicit Euler on RPM is weak; rotorpy's exact-exponential discretization technique applies directly to the linearized version of this ODE.

### FGRotor dynamic inflow: Glauert momentum equilibrium + first-order inflow lag with exact exponential discretization — **ADOPTED (candidate tier)**

- **Equations:** Nondimensional, control(wind) axes at the hub; all velocities normalized by tip speed Omega*R [ft/s]. Advance ratio mu = U_w/(Omega*R), clamped mu <= 0.7 (SH79 eqn 24). Inflow ratio lambda = W_w/(Omega*R) - nu (SH79 eqn 25), where nu = induced inflow ratio, U_w/W_w = in-plane/normal hub aero velocity components. Blade-element thrust coefficient (Bailey /BA41/ closed form, tip-loss factor B, linear twist theta_tw): C_T/sigma = (a/2)*[ (B^2/2 + mu^2/4)*lambda + (B^3/3 + B*mu^2/2 - 4*mu^3/(9*pi))*theta_0 + (B^4/4 + B^2*mu^2/4)*theta_tw ] (SH79 eqn 27). Momentum-equilibrium inflow: c0 = C_T / (2*sqrt(mu^2 + lambda^2) + 1e-15) (Glauert). Dynamic inflow ODE: dnu/dt = (1/tau)*(C_T/(2*sqrt(mu^2+lambda^2)) - nu), integrated holding mu, lambda constant over the step: nu <- flow_scale * ((nu - c0)*exp(-dt/tau) + c0), where flow_scale in [0.5, 1] is the ground-effect factor. Then Thrust = b*c*R*rho*(Omega*R)^2 * (C_T/sigma) [lbf]; v_i = nu*Omega*R [ft/s]; C_T = (C_T/sigma)*sigma; sigma = b*c/(pi*R) = solidity. Inflow time constant estimate tau = 16/(gamma*Omega) (GE49 eqn 1) with Lock number gamma = rho*a*c*R^4/I_b. Symbols: a = blade lift-curve slope [1/rad], b = blade count, c = chord [ft], R = radius [ft], theta_0 = collective pitch [rad], I_b = blade flapping inertia [slug*ft^2], rho [slug/ft^3], Omega [rad/s].
- **Source:** JSBSim master @ 9a0b028, src/models/propulsion/FGRotor.cpp lines 412-451 (calc_flow_and_thrust), 343-351 (Lock number, tau estimate), 420-421 (mu clamp); references documented in FGRotor.h lines 210-224: /SH79/ Shaughnessy, Deaux, Yenni, NASA TP-1285 (1979) eqns 24-27; /BA41/ Bailey, NACA Rep. 716 (1941); /GE49/ Gessow & Amer, NACA TN-1982 (1949) eqn 1
- **Parameters:** defaults in Configure(): a = 6.0 /rad, theta_tw = -0.17 rad, B (tip loss) = 1.0, tau (inflowlag) typical 0.1-0.2 s for full-size main rotor (scales as 1/(gamma*Omega): for a small UAV prop at 8000 RPM with gamma~5, tau ~ 4 ms)
- **Relevance:** This is the biggest transferable item. It gives thrust as a function of collective (blade pitch), edgewise speed mu, AND axial inflow lambda simultaneously — i.e., a single closed-form model producing translational-lift, climb-thrust-loss, and descent-thrust-gain effects that the spec currently approximates with three separate fitted terms (k_h translational lift, k_v2 climb term, atan2 corrections). The dynamic inflow state nu with exact exponential discretization matches the spec's existing discretization philosophy and is fully differentiable (JAX-friendly). Fixed-pitch adaptation: theta_0 becomes a constant of the prop, thrust control enters through Omega.
- **Notes:** Strong provenance (NASA TP-1285 is a validated piloted-sim model). Caution: coefficients assume rectangular, linearly twisted, articulated blades and small angles; for small stiff props the C_T/sigma polynomial coefficients should be refit rather than taken literally. The mu <= 0.7 clamp and the 1e-15 sqrt guard are numerical, not physical.

### Rotor coning angle (quasi-static) — *skipped*

- **Equations:** a0 = gamma * [ (1/6 + 0.04*mu^3)*lambda + (1/8 + mu^2/8)*theta_0 + (1/10 + mu^2/12)*theta_tw ] [rad], gamma = Lock number = rho*a*c*R^4/I_b (dimensionless), evaluated in control axes. (SH79 eqn 29.)
- **Source:** JSBSim master @ 9a0b028, src/models/propulsion/FGRotor.cpp lines 456-468; /SH79/ NASA TP-1285 eqn 29
- **Parameters:** gamma via LockNumberByRho*rho, see FGRotor.cpp line 343
- **Relevance:** Coning matters when blade flapping inertia is low relative to aero forces (articulated/teetering rotors). Small multirotor props are torsionally and flapwise stiff with high effective hinge stiffness; coning is sub-degree and its force resultant is already absorbed into measured k_eta. Not worth a state or parameter for a quadrotor.
- **Notes:** Only becomes relevant for large flexible-blade multirotors (agriculture-scale).

### First-harmonic blade flapping with body-rate damping terms (rotor damping in pitch/roll) — **ADOPTED (candidate tier)**

- **Equations:** Control(wind) axes, quasi-static tip-path-plane tilt [rad]: a_1 = [ (2*lambda + (8/3)*theta_.75)*mu + p_w/Omega - 16*q_w/(gamma*Omega) ] / (1 - mu^2/2) (longitudinal flap); b_1 = [ (4/3)*mu*a0 - q_w/Omega - 16*p_w/(gamma*Omega) ] / (1 + mu^2/2) (lateral flap); theta_.75 = theta_0 + 0.75*theta_tw (blade pitch at 75% radius). p_w, q_w = fuselage roll/pitch rates expressed in control axes [rad/s], Omega = rotor speed [rad/s], gamma = Lock number. (SH79 eqn 32; rate terms per /AM50/ Amer NACA TN-2136.) Downstream force use: H_drag = T * a_dw with a_dw = [ (2*lambda + (8/3)*theta_.75)*mu - 24*q_w/(gamma*Omega)*(1 - 0.29*theta_.75/(C_T/sigma)) ] / (1 - mu^2/2) (SH79 eqn 38-region). Resulting hub moments from hinge offset e [ft]: M_roll = 0.5*e*b*Omega^2*M_b*b1s, M_pitch = 0.5*e*b*Omega^2*M_b*a1s [ft*lbf], M_b = blade mass moment [slug*ft], a1s/b1s = flapping resolved to shaft axes minus cyclic input (SH79 eqn 43, FGRotor.cpp lines 589-597).
- **Source:** JSBSim master @ 9a0b028, src/models/propulsion/FGRotor.cpp lines 474-502 (calc_flapping_angles), 584-600 (body_moments); /SH79/ NASA TP-1285 eqn 32, 43; /AM50/ NACA TN-2136 (1950)
- **Parameters:** gamma, e (hinge offset, default 0.05*R), M_b (BladeMassMoment)
- **Relevance:** rotorpy's -kflap*W*(v x z) captures the velocity-driven (mu) part of flapping only. The NEW physics here is the body-rate terms p_w/Omega and 16*q_w/(gamma*Omega): the tip-path plane lags a rolling/pitching body, producing rotor damping moments proportional to body rate — a genuine, measurable damping derivative on multirotors (documented in the quadrotor literature as rotor/blade-flapping damping). For stiff props the hinge-offset hub-moment constant becomes an effective hub stiffness, but the rate-dependence structure transfers.
- **Notes:** Minimal adoption: add a per-rotor moment term M = -k_rate_flap * W * (p, q) style damping derived from a_1, b_1 rate terms, one new parameter. Provenance solid (NACA TN-2136). Full SH79 flapping is overkill for stiff-prop quadrotors.

### Rotor H-force (in-plane drag force) and side force — already covered

- **Equations:** H_drag = T*a_dw [lbf] along -x of wind/control axes; side force J_side = b*c*R*rho*(Omega*R)^2*(C_Y/sigma) [lbf], with C_Y/sigma = (a/2)*[0.75*b_1*lambda - 1.5*a0*mu*lambda + 0.25*a_1*b_1*mu - a0*a_1*mu^2 + (1/6)*a0*a_1 - (0.75*mu*a0 - (1/3)*b_1 - 0.5*mu^2*b_1)*theta_.75] (SH79 eqns 38, 39). Forces then rotated from control axes to shaft to body axes (FGRotor.cpp lines 569-577).
- **Source:** JSBSim master @ 9a0b028, src/models/propulsion/FGRotor.cpp lines 508-525 (calc_drag_and_side_forces), 569-577 (body_forces)
- **Parameters:** derived from flapping state, no new free parameters
- **Relevance:** rotorpy already models the same aggregate effect as rotor-drag H-force -W*diag(kd,kd,kz)*v_local per rotor including lever arm. JSBSim's version derives the coefficient from blade theory rather than fitting kd; for a quadrotor sim the fitted linear form is the established practice and equivalent at first order in mu.
- **Notes:** If a physics-derived kd is ever wanted: kd ~ T*(2*lambda + (8/3)*theta_.75)/(Omega*R) from the a_dw expression, giving kd's dependence on thrust and RPM.

### Rotor aerodynamic torque with forward-flight profile term and induced/climb components — **ADOPTED (candidate tier)**

- **Equations:** Q = rho*b*c*delta*(Omega*R)^2*R^2*(1 + 4.5*mu^2)/8 - (T*lambda + H*mu)*R [ft*lbf], with profile-drag coefficient estimated as delta = 0.009 + 0.3*(6*C_T/(a*sigma))^2 (drag polar in mean lift coefficient). First term = blade profile power torque growing with edgewise speed as (1+4.5*mu^2); second term = induced + climb torque (lambda < 0 in hover: -T*lambda*R > 0 adds torque). From Bramwell's Helicopter Dynamics 2nd ed. eqns 3.43, 3.44 (simplified SH79 eqn 36).
- **Source:** JSBSim master @ 9a0b028, src/models/propulsion/FGRotor.cpp lines 529-543 (calc_torque); code comment cites Bramwell 2nd ed. eqn 3.43/3.44
- **Parameters:** delta_0 = 0.009, delta_2 = 0.3 (hardcoded blade drag-polar constants)
- **Relevance:** rotorpy's per-rotor torque is a polynomial in Omega alone (c0+c1*W+c2*W^2 with k_m). This adds the flight-condition dependence: torque (hence battery power and yaw authority) rises with edgewise airspeed as (1+4.5*mu^2) and falls in descent (lambda term) — real effects for endurance modeling and yaw-torque prediction in fast forward flight. Moderate value; second-order for typical hover-centric sims.
- **Notes:** Published provenance (Bramwell). Cheap: multiply existing k_m torque by (1 + 4.5*mu^2) and add -(T*lambda + H*mu)*R if inflow state exists. Only worth it together with the dynamic-inflow adoption, since it needs lambda and mu.

### In-ground-effect factor (inflow reduction, exponential in height) — **ADOPTED (candidate tier)**

- **Equations:** ge_factor = 1 - s_norm * exp(-(h_agl_filtered + h_shift)*k_ge) * (RPM/NominalRPM), clamped to [0.5, 1.0]; h_agl_filtered = first-order low-pass of height above ground [ft] (source comment says 1 Hz, but Filter(1.0, dt) places the pole at 1 rad/s ≈ 0.16 Hz — verification finding); the factor multiplies the induced inflow state: nu <- ge_factor * nu (see dynamic inflow equation), so reduced inflow => larger lambda => larger C_T => more thrust near ground. Symbols: k_ge = groundeffectexp [1/ft] (0.04 large rotors ... 0.1 small rotors; effect vanishes ~2-3 rotor diameters), h_shift = groundeffectshift ~ hub height [ft], s_norm = runtime scale in [0,1] (property groundeffect-scale-norm, e.g. to kill the effect above ~50 kt).
- **Source:** JSBSim master @ 9a0b028, src/models/propulsion/FGRotor.cpp lines 639-646 (CalcRotorState), 335-336 (config), 211-213 (1 Hz hagl filter), FGRotor.h lines 130-138 (parameter doc); code comment at FGRotor.cpp lines 408-410 credits the inflow-scaling idea to /TA77/ Talbot & Corliss, NASA TM-73,254 (1977) eqn 10a
- **Parameters:** k_ge ~ 0.04-0.1 1/ft, shift ~ hub height, hard clamp at 0.5 max effect
- **Relevance:** Ground effect is absent from rotorpy's verified inventory and is a first-order effect for small quadrotors below ~2 rotor diameters altitude (landing, takeoff, low hover). JSBSim's exponential-in-height inflow scaling is empirical but has TM-provenance; the quadrotor literature more commonly uses Cheeseman-Bennett T_IGE/T_OGE = 1/(1 - (R/(4z))^2) per rotor (Cheeseman & Bennett, ARC R&M 3021, 1955), which is closed-form in z and has published multirotor validations (e.g. Sanchez-Cuevas et al. 2017). Either way this fills a real gap.
- **Notes:** Two implementation lessons transfer regardless of formula choice: (1) low-pass the height-above-ground input to avoid force discontinuities from terrain steps; (2) scale the effect by rotor loading (JSBSim uses RPM/NominalRPM) and expose a runtime kill-switch for forward flight. Applying the factor to induced velocity (not directly to thrust) is the more physical route and composes with a dynamic-inflow state. ⚠ Verification finding (landed as spec.ground_effect.talbot_inflow_factor): JSBSim multiplies the PERSISTENT inflow state by the factor every step, which compounds through the lag filter — the steady-state reduction is nu* = f·c0·(1−e)/(1−f·e), e = exp(−dt/τ), timestep-dependent and far stronger than f for small dt. The spec form applies f_GE once to the quasi-steady inflow instead; do not reproduce the per-step state rescale.

### ISA / US Standard Atmosphere 1976: density from ideal gas law, thrust explicitly proportional to rho — **ADOPTED (candidate tier)**

- **Equations:** rho = P/(R_dry*T) [slug/ft^3] (ideal gas, FGAtmosphere.cpp lines 186-189, 212-214). T(h): piecewise-linear lapse table in geopotential altitude H = h*R_E/(R_E + h), R_E = 6356766 m / 0.3048 ft (FGStandardAtmosphere.h lines 319, 361). P(h) per USSA-1976 eqns 33a/33b: gradient layer (L_b != 0): P = P_b*(T_b/(T_b + L_b*(H - H_b)))^(g0/(R_dry*L_b)); isothermal layer: P = P_b*exp(-g0*(H - H_b)/(R_dry*T_b)), with P_b, T_b, H_b, L_b the base pressure/temperature/geopotential-altitude/lapse-rate of the enclosing layer (troposphere: H_b=0, L_b = -0.00356616 R/ft i.e. -6.5 K/km). a_sound = sqrt(gamma_air*R_dry*T). Thrust rho-scaling is explicit and linear in both thruster models: FGPropeller.cpp line 249 (Thrust = ThrustCoeff*RPS*RPS*D4*rho) and line 369 (PowerRequired ~ rho), FGRotor.cpp line 446 (Thrust = ...*rho*...). The engine models do NOT rescale for the propeller — all density dependence of thrust/torque lives in the thruster equations.
- **Source:** JSBSim master @ 9a0b028, src/models/FGAtmosphere.cpp lines 84-86, 153-196, 212-214; src/models/atmosphere/FGStandardAtmosphere.cpp lines 190-224 (GetPressure), 248-272 (GetTemperature), 324-327 (GetStdDensity); FGStandardAtmosphere.h lines 319-322, 361

- **Relevance:** rotorpy's inventory has no altitude-density model: k_eta/k_m are constants fit at one density. - **Notes:** One layer of USSA-1976 is 3 lines of differentiable code — high value/cost ratio for a sim intended to generalize across test sites. Full multi-layer table is unnecessary for small UAVs.

### Brushless DC motor three-constant model (Drela/QPROP) with no-load-current deadband — **ADOPTED (candidate tier)**

- **Equations:** V = V_max*u (u = throttle in [0,1]); I = (V - RPM/Kv)/R_m [A] (back-EMF law, Drela eqn 4); torque with friction deadband: Q = (I - I0)/Kv * k_unit if I >= I0; Q = (I + I0)/Kv * k_unit if I <= -I0; else Q = 0, where k_unit = WattperRPMtoftpound converts (A * V/RPM_units) to ft*lbf; shaft power P = Q*omega = 2*pi*max(RPM, 1e-4)*Q/60 [ft*lbf/s]. Symbols: Kv = speed constant [RPM/V], R_m = winding resistance [Ohm], I0 = no-load current [A] (models friction; always opposes rotation), V_max = supply voltage [V]. Torque constant Kq = 1/Kv in consistent units. This power then drives the FGPropeller torque-balance shaft ODE (see shaft-speed dynamics finding), closing V -> I -> Q_m -> omega -> J -> Q_aero.
- **Source:** JSBSim master @ 9a0b028, src/models/propulsion/FGBrushLessDCMotor.cpp lines 124-157 (Calculate), 29-38 (header: 'Kv [RPM/Volt], Rm [Ohms], I0 [Amperes]'); reference cited in file: M. Drela, 'First-Order DC Electric Motor Model' (QPROP theory doc), http://web.mit.edu/drela/Public/web/qprop/motor1_theory.pdf
- **Parameters:** Kv [RPM/V], R_m [Ohm], I0 [A], V_max [V]; MaxCurrent = V_max/R_m + I0
- **Relevance:** Directly relevant to quadrotors and more physical than the spec's fitted chain (throttle curve + V->RPM polynomial sag + first-order lag): it predicts current draw I per motor (feeds a battery model: V_batt = V_oc - I_total*R_batt reproduces voltage sag mechanistically), steady-state RPM under load, and — coupled to the shaft ODE — the spin-up/down asymmetry the spec hand-fits. Kv, R_m, I0 are datasheet quantities for hobby motors. Fully differentiable (the deadband needs a smooth approximation for JAX).
- **Notes:** Strongest single adoption candidate alongside dynamic inflow. Gaps in JSBSim's version: constant V_max (no battery state — rotorpy's sag model actually covers something JSBSim lacks), no ESC PWM/commutation losses, motor efficiency eta = (1 - I0/I)*(1 - I*R_m/V) implied but not exposed. Drela's doc is public and gives the derivation.

## Ground effect & inter-vehicle downwash literature

Ground effect and vehicle-to-vehicle downwash are entirely absent from the existing rotorpy inventory (verified by grep), so all four primary models are new adopt-candidates. Recommended spec structure: (1) per-rotor ground effect as a multiplicative thrust ratio - Cheeseman-Bennett 1/(1-(R/4z)^2) as the base (valid 0.5<=z/R<=2, singular at z=R/4, clamp z), upgraded for quadrotors with Sanchez-Cuevas 2017 Eqs. (3)-(4) adding adjacent-rotor (d), diagonal-rotor (sqrt(2)d), and fountain/body-lift (b, K_b~2) image terms, significant to z~5R; (2) gym-pybullet-drones offers the simplest differentiable per-rotor variant (additive increment kf*rpm^2*G*(R/4h)^2, G=11.36859, R=0.0231348 m for CF2, verbatim code at BaseAviary.py L688-725/L760-786 with height clip L126) plus an empirical CoM-applied Gaussian downwash (alpha=2267.18*(R/4dz)^2 N, beta=0.16*dz-0.11 m) whose limits (thrust-independent, unreliable below dz~0.7 m, no induced moment) are documented; (3) Jain et al. ICUAS 2019 is the physically-grounded downwash model - momentum-theory jet with 1/(z-z0) centerline decay and Gaussian radial profile (fitted c_ax~4.7-4.9, c_rad 24.9-60.8, z0 0.033-0.110 m), frame drag C_D=1.18, and per-rotor thrust loss -b_v*v_on*omega^2 (b_v=3.71e-7 N m^-1 rad^-2 s^3) - and couples naturally to rotorpy's per-rotor architecture, with one double-counting hazard: downwash-induced inflow must feed the EXISTING advance-ratio thrust correction OR Jain's Delta_f_p, not both. Learned models (Neural-Lander, Neural-Swarm, Gielis 2023) are not spec-adoptable but supply two caveats: steady GE models miss unsteady descent effects, and pairwise-additive downwash breaks down with 2+ upper neighbors in dense formation.

### Cheeseman-Bennett in-ground-effect thrust ratio (single rotor, hover + forward flight) — **ADOPTED (candidate tier)**

- **Equations:** Hover (potential-flow, method of images): T_IGE / T_OGE = 1 / (1 - (R/(4 z))^2). Symbols: T_IGE = rotor thrust in ground effect [N] at same power/RPM; T_OGE = thrust out of ground effect [N]; R = rotor radius [m]; z = height of rotor disk plane above ground, measured along the ground-plane normal [m]. Dimensionless ratio; apply as multiplicative factor on nominal thrust. Derivation: rotor modeled as 3D potential point source of strength s = R^2 * v_i / 4 (v_i = induced velocity at rotor [m/s]) plus a mirror-image source at -z enforcing zero normal flow through the ground; velocity potential phi = -s/sqrt(x^2+y^2+(z-z0)^2). Forward-flight generalization (commonly cited C-B 1955 result; verify against R&M 3021 before adoption): T_IGE / T_OGE = 1 / (1 - (R/(4 z))^2 * 1/(1 + (V/v_i)^2)), where V = horizontal airspeed [m/s] and v_i = sqrt(T/(2 rho A)) hover induced velocity [m/s], rho = air density [kg/m^3], A = pi R^2 rotor disk area [m^2]; ground effect washes out with forward speed.
- **Source:** Cheeseman, I.C., and Bennett, W.E., 'The Effect of the Ground on a Helicopter Rotor in Forward Flight', ARC R&M 3021, 1955. Hover form and derivation verified verbatim as Eq. (1)-(2) of Sanchez-Cuevas, Heredia, Ollero 2017 (Int. J. Aerospace Eng., doi 10.1155/2017/1823056, Section 2.1); validity range quoted from Hooi, Lagor, Paley, 'Height Estimation and Control of Rotorcraft in Ground Effect', J. American Helicopter Society 2016 (cdcl.umd.edu/papers/jahs16.pdf): 'The Cheeseman and Bennett model is used to relate TIGE and height h in hover for 0.5 <= h/R <= 2.0'.
- **Parameters:** No free parameters beyond R and z (v_i, V for the forward-flight form). Validity: singular at z = R/4, so physically meaningful only for z/R > 0.25; experimentally validated 0.5 <= z/R <= 2.0 (helicopter literature); increment is 1.6% at z/R = 2 and 0.7% at z/R = 3, so negligible above z/R ~ 3 for a single rotor. Sanchez-Cuevas 2017 confirmed the single-rotor form experimentally on small rotors (R = 0.12 m and R = 0.205 m).
- **Relevance:** Baseline ground-effect model for any rotor near terrain; cheap, smooth, differentiable (JAX-friendly), and per-rotor applicable (each rotor uses its own z), which also produces the partial-ground-effect disturbance moment near ledges. Not in the existing inventory (no ground-effect term exists in rotorpy today; verified by grep of the rotorpy source tree, no matches for ground_effect/downwash).
- **Notes:** Known to UNDER-predict ground effect for a full multirotor (see Sanchez-Cuevas finding). Guard the singularity: clamp z >= ~0.5R (gym-pybullet-drones clamps equivalently). Constant-power assumption: the ratio expresses thrust gain at fixed power/RPM.

### Sanchez-Cuevas 2017 multirotor ground effect: quadrotor PFI with mirrored rotors (Eq. 3) + empirical body-lift term (Eq. 4), and partial ground effect — **ADOPTED (candidate tier)**

- **Equations:** Quadrotor PFI, Eq. (3): T_IGE / T_OGE = 1 / ( 1 - (R/(4 z))^2 - R^2 * z / (d^2 + 4 z^2)^(3/2) - (R^2 / 2) * z / (2 d^2 + 4 z^2)^(3/2) ). With body lift, Eq. (4): T_IGE / T_OGE = 1 / ( 1 - (R/(4 z))^2 - R^2 * z / (d^2 + 4 z^2)^(3/2) - (R^2 / 2) * z / (2 d^2 + 4 z^2)^(3/2) - 2 R^2 * K_b * z / (b^2 + 4 z^2)^(3/2) ). Symbols: R = rotor radius [m]; z = rotor-plane height above ground [m] (all four rotors coplanar); d = distance between adjacent rotor axes [m]; b = distance between opposite (diagonal) rotor axes [m], b = sqrt(2)*d for a square layout; K_b = dimensionless empirical body-lift coefficient. Derivation: one potential source per rotor at (0,0,z),(0,d,z),(d,0,z),(d,d,z) plus 4 mirror images at -z; the d-term aggregates the two adjacent-rotor images, the sqrt(2)d-term the diagonal image; the K_b term models fountain-effect flow recirculation impinging on the central body. All terms dimensionless. Frame: z along ground normal; ratio multiplies total (or per-rotor) hover thrust.
- **Source:** Sanchez-Cuevas, P., Heredia, G., Ollero, A., 'Characterization of the Aerodynamic Ground Effect and Its Influence in Multirotor Control', International Journal of Aerospace Engineering, 2017, Article 1823056, doi 10.1155/2017/1823056, Sections 2.2-2.3, Eqs. (3) and (4). Equations extracted verbatim from the open-access PDF (orbilu.uni.lu/bitstream/10993/47153/1/1823056.pdf).
- **Parameters:** K_b ~ 2 ('takes a value close to 2 in the experiments performed', fitted on PQUAD quadrotor: 4 rotors, R = 0.12 m, total mass 1.4 kg; also tested AMUSE octorotor: 8 rotors, R = 0.205 m, 12 kg). Geometry inputs d and b come from the airframe. Validity: multirotor ground effect 'significant for distances to the ground of up to 5 rotor radii' (vs 2R for a single rotor); same z > R/4 singularity guard applies to every denominator term.
- **Relevance:** The credible published multirotor-specific extension of Cheeseman-Bennett; captures the experimentally observed amplification (fountain effect) that Eq. (2) misses. Directly parameterized by the spec's existing rotor geometry (rotor positions give d, b). Partial ground effect (Section 2.3): applying the single-rotor ratio per rotor with each rotor's own z reproduces the disturbing moment when only some rotors are IGE; paper reports 1-rotor-IGE matches the single-rotor model and 3-rotor-IGE lies between single-rotor and full-quad curves.
- **Notes:** Eq. (4) assumes hover over flat ground with all rotors coplanar at equal z; for per-rotor/partial-GE simulation a reasonable spec is: per-rotor Cheeseman-Bennett term with own z_i plus shared interference/body terms evaluated at mean z, or full Eq. (4) blended per-rotor - the paper itself only validates the symmetric case and the 1-of-4/3-of-4 bench cases. Not covered by any existing inventory item.

### gym-pybullet-drones per-propeller ground effect (_groundEffect) — **ADOPTED (candidate tier)**

- **Equations:** Per propeller i (i = 0..3): F_ge,i = rpm_i^2 * KF * G * (R_prop / (4 * h_i))^2, applied as force [0, 0, F_ge,i] in the propeller LINK_FRAME (i.e., along body +z at each rotor hub, giving both net force and, for tilted/uneven heights, a moment). Symbols: rpm_i = motor speed [RPM]; KF = thrust constant [N/RPM^2] (thrust model F_i = KF * rpm_i^2); G = GND_EFF_COEFF, dimensionless fitted coefficient; R_prop = propeller radius [m]; h_i = world-frame z (height above ground plane) of propeller link i [m], clipped below at GND_EFF_H_CLIP. GND_EFF_H_CLIP = 0.25 * R_prop * sqrt(15 * MAX_RPM^2 * KF * G / MAX_THRUST); with MAX_THRUST = 4*KF*MAX_RPM^2 this simplifies to (R_prop/4)*sqrt(15*G/4) = 0.0378 m ~ 1.63*R_prop for CF2, which caps per-prop GE force at (rpm/MAX_RPM)^2 * MAX_THRUST/15. Effect disabled when |roll| >= pi/2 or |pitch| >= pi/2. This is the first-order expansion of a Cheeseman-Bennett-type ratio: delta_T = T * mu * (R/4z)^2, matching the steady comparison model in Neural-Lander (Shi et al. 2019), T(n,z) = c_T(n) * n^2 / (1 - mu*(D/(8 z))^2) with D = 2R (D/8z = R/4z), mu fitted.
- **Source:** gym_pybullet_drones/envs/BaseAviary.py (utiasDSL/gym-pybullet-drones, master branch fetched 2026-08-10): def _groundEffect at L688; height clip L713; force formula L714 verbatim 'gnd_effects = np.array(rpm**2) * self.KF * self.GND_EFF_COEFF * (self.PROP_RADIUS/(4 * prop_heights))**2'; attitude guard L715; GND_EFF_H_CLIP defined L126. Docstring L694: 'Inspired by the analytical model used for comparison in (Shi et al., 2019)' [Neural-Lander, ICRA 2019, arXiv:1811.08027, Eq. (15)]. Parameter parsing L966-996 (_parseURDFParameters).
- **Parameters:** From gym_pybullet_drones/assets/cf2x.urdf line 5 (Crazyflie 2.x, mass 0.027 kg): kf = 3.16e-10 N/RPM^2, km = 7.94e-12 N*m/RPM^2, prop_radius = 2.31348e-2 m, gnd_eff_coeff = 11.36859 (dimensionless), arm = 0.0397 m, thrust2weight = 2.25. Note G = 11.37 >> 1 encodes the multirotor/fountain amplification for the CF2 (at h = R it gives +71% per-prop thrust before the clip saturates it).
- **Relevance:** Battle-tested, per-rotor, smooth and trivially differentiable ground-effect increment - the natural form for the planned JAX port; per-rotor application automatically yields partial-ground-effect moments. Uses only quantities already in rotorpy's rotor model (per-rotor speed, k_eta-equivalent thrust constant, rotor positions).
- **Notes:** Additive-increment (linearized) form avoids the C-B singularity but needs the height clip to bound force; flat-ground assumption (h = world z of prop). The multiplicative Sanchez-Cuevas Eq. (4) is the better-published alternative; this one's virtue is per-rotor simplicity plus a concrete identified coefficient for the CF2 platform. No overlap with existing inventory.

### gym-pybullet-drones inter-vehicle downwash (_downwash, DSL/SiQi Zhou empirical Gaussian model) — **ADOPTED (candidate tier)**

- **Equations:** For every other vehicle i with delta_z = z_i - z_ego > 0 and horizontal separation delta_xy = ||p_i,xy - p_ego,xy|| < 10 m: F_dw = [0, 0, -alpha * exp(-0.5 * (delta_xy / beta)^2)] applied at the ego vehicle CoM in LINK_FRAME (body z, downward force). alpha = c1 * (R_prop / (4 * delta_z))^2 [N]; beta = c2 * delta_z + c3 [m]. Symbols: delta_z, delta_xy = vertical/horizontal CoM separation [m]; R_prop = propeller radius [m]; c1 [N] sets peak magnitude (inverse-square decay with delta_z, same (R/4z)^2 kernel as the ground-effect image model); c2 [-] and c3 [m] set the linear growth of the Gaussian wake width with vertical separation (free-jet-like spreading).
- **Source:** gym_pybullet_drones/envs/BaseAviary.py (utiasDSL/gym-pybullet-drones, master, fetched 2026-08-10): def _downwash L760; verbatim L777-779: 'alpha = self.DW_COEFF_1 * (self.PROP_RADIUS/(4*delta_z))**2; beta = self.DW_COEFF_2 * delta_z + self.DW_COEFF_3; downwash = [0, 0, -alpha * np.exp(-.5*(delta_xy/beta)**2)]'. Docstring L765: 'Based on experiments conducted at the Dynamic Systems Lab by SiQi Zhou' (no separate publication cited in-code).
- **Parameters:** cf2x.urdf line 5: dw_coeff_1 = 2267.18 [N], dw_coeff_2 = 0.16 [-], dw_coeff_3 = -0.11 [m]; prop_radius = 2.31348e-2 m; CF2 weight = 0.265 N. Sanity check: directly below at delta_z = 1 m -> 0.0758 N (29% of weight, consistent with reported Crazyflie stacking losses); at delta_z = 0.5 m -> 0.303 N (114% of weight, implausibly strong - the fit is not trustworthy below ~0.7 m).
- **Relevance:** Only widely-used open-source vehicle-to-vehicle downwash force model; two-line, differentiable, and gives rotorpy multi-vehicle interaction at near-zero cost. Not in existing inventory.
- **Notes:** Caveats to state in any spec: (a) force is independent of the upper vehicle's RPM/thrust and mass - it is a CF2-specific fit; (b) beta <= 0 for delta_z <= 0.6875 m (beta enters squared so sign is harmless, but beta = 0 with delta_xy = 0 yields 0/0 = NaN, and the near-field is outside the fit's validity anyway); (c) applied at CoM only - no induced moment when offset laterally, unlike Jain et al.; (d) hard cutoff at delta_xy = 10 m. Prefer refitting c1 as c1' * (T_upper/T_hover) if thrust scaling is wanted.

### Jain et al. 2019 proximity-flight downwash: Gaussian turbulent-jet velocity field + frame drag + per-rotor thrust loss — **ADOPTED (candidate tier)**

- **Equations:** Velocity field of the upper vehicle's wake in its zone of established flow (ZEF, z > 3L), axisymmetric, axial component only, axial direction = upper vehicle's body -z (downward), assumed aligned with inertial -z in hover. Eq. (1) centerline decay: V_max(z) = sqrt(T / (2 rho A_p)) * c_ax * L / (z - z0). Eq. (2) radial Gaussian profile: V(z, r) = V_max(z) * exp( -c_rad * (r / (z - z0))^2 ). Symbols: T = per-propeller thrust of upper vehicle [N]; rho = air density [kg/m^3]; A_p = propeller disk area [m^2]; sqrt(T/(2 rho A_p)) = momentum-theory induced velocity V_i [m/s]; L = vehicle size = 2 * arm length [m]; z = axial (vertical) separation [m]; r = radial (horizontal) separation [m]; z0 = virtual origin [m]; c_ax, c_rad dimensionless fitted constants; wake width grows linearly with z (free shear flow). Disturbance on lower vehicle: Eq. (3) frame drag F_D(z,r) = integral over frame area A_q of (-z_B) * (1/2) * C_D * rho * V^2(z',r') dA with flat-plate C_D = 1.18; Eq. (4) drag torque T_D = integral (r' - r_cm) x (-z_B) * (1/2) C_D rho V^2 dA (zero yaw component in hover); Eqs. (5)-(6) per-propeller thrust change from oncoming axial flow: f_p = k2(v_on) * omega_p^2 with k2(v_on) = k1 - b_v * v_on, so Delta_f_p,i = -b_v * v_on(z_i, r_i) * omega_p,i^2; Eqs. (7)-(8): F_P = sum_i z_B * Delta_f_p,i, T_P = sum_i (r_i - r_cm) x z_B * Delta_f_p,i. Symbols: omega_p = propeller speed [rad/s]; v_on = oncoming (downwash) axial velocity at propeller i [m/s] from Eq. (2); b_v = thrust decay coefficient [N m^-1 rad^-2 s^3]; z_B = lower vehicle body z unit vector.
- **Source:** Jain, K.P., Fortmuller, T., Byun, J., Makiharju, S.A., Mueller, M.W., 'Modeling of aerodynamic disturbances for proximity flight of multirotors', ICUAS 2019, pp. 1261-1269. Equations (1)-(8) and all constants extracted verbatim from the author PDF at hiperlab.berkeley.edu/wp-content/uploads/2019/05/Modeling_of_aerodynamic_disturbances_for_proximity_flight_of_multirotors.pdf, Sections II-A/B/C and IV-B/C.
- **Parameters:** Fitted (least squares, flow-probe data, consistent across thrust levels): small quadcopter: c_ax = 4.672, z0 = 0.033 m, c_rad = 60.808; large quadcopter: c_ax = 4.886, z0 = 0.110 m, c_rad = 24.936; C_D = 1.18 (flat plate); b_v = 3.710e-7 N m^-1 rad^-2 s^3 (their propeller). Constants are vehicle-geometry dependent; c_ax matches published axisymmetric turbulent-jet values.
- **Relevance:** The most physically grounded published vehicle-to-vehicle downwash model: thrust-dependent (unlike the gym-pybullet-drones fit), gives both force AND induced roll/pitch moment on the lower vehicle, and its per-rotor v_on plugs directly into rotorpy's per-rotor structure. Recommended primary adopt-candidate for downwash between vehicles; can also be evaluated per-rotor-pair or with the frame integral collapsed to a single point evaluation times reference area for speed.
- **Notes:** Overlap warning, not duplication: Delta_f_p = -b_v * v_on * omega^2 is the same physics as the existing inventory's 'thrust vs angle-of-attack/advance-ratio multiplicative correction' and k_v2*vz*|vz| climb term (thrust loss under axial inflow) - a spec must route downwash-induced v_on through ONE of these paths to avoid double counting (cleanest: add v_on to the local air velocity seen by the existing rotor inflow/drag models). Model is hover-to-hover, ZEF-only (z > 3L); near-field (z < 3L) is explicitly out of scope.

### Learned interaction models: Neural-Lander, Neural-Swarm/Neural-Swarm2, Gielis et al. aggregate downwash — *skipped*

- **Equations:** Neural-Lander (Shi et al., ICRA 2019, arXiv:1811.08027): dynamics m*dv/dt = m*g + R*f_u + f_a with f_a = [f_a,x, f_a,y, f_a,z] the unmodeled aerodynamic force learned by a spectrally-normalized DNN from flight data (f_a = m*dv/dt - m*g - R*f_u); their steady analytical comparison model, Eq. (15): T(n, z) = c_T(n) * n^2 / (1 - mu * (D/(8 z))^2), n = rotor speed, D = rotor diameter [m], z = height [m], c_T = thrust coefficient, mu = fitted coefficient - i.e., Cheeseman-Bennett with an empirical gain (this is the model gym-pybullet-drones linearizes). Neural-Swarm2 (Shi et al., T-RO 2022, arXiv:2003.02992 for v1): permutation-invariant deep sets over neighbor relative states predicting interaction forces. Gielis, Shankar, Kortvelesy, Prorok, 'Modeling Aggregate Downwash Forces for Dense Multirotor Flight', DARS 2023 / arXiv:2312.03488: 6-DOF load-stand measurements show pairwise-additive single-neighbor downwash models f_total = sum_j f(x_j) break down (strong nonlinear aggregation) for K >= 2 neighbors within 1-3 body lengths; graph/deep-set model fits better.
- **Source:** Shi, G. et al., 'Neural Lander: Stable Drone Landing Control using Learned Dynamics', ICRA 2019, arXiv:1811.08027 (Secs. I, VI, Eq. 15, read via ar5iv); Shi, G. et al., 'Neural-Swarm2', IEEE T-RO 2022 / arXiv:2003.02992; Gielis, J. et al., arXiv:2312.03488 (DARS 2023), abstract and Sec. 1 read from PDF.
- **Parameters:** None analytically transferable (trained network weights). Neural-Lander context: existing theoretical ground-effect models are steady-flow, and their DNN outperformed the steady model especially under nonzero vertical velocity; measured f_a,z on their Intel Aero (1.47 kg) near ground was order 0.5-2 N (3-13% of weight).
- **Relevance:** Not adoptable in a physics spec (no closed form, platform-specific weights), but two spec-relevant facts: (a) the steady C-B family under-represents unsteady GE during descent/climb - worth a caveat in the spec; (b) any pairwise-additive downwash model (Jain, gym-pybullet-drones) should be flagged as valid only for a single upper neighbor / sparse formations, per Gielis et al.
- **Notes:** Documenting these as validity caveats on the adopt-candidates rather than as models.

Caveats: Mahony RAM 2012 itself is paywalled everywhere legitimate (ANU restricted to 2037) — its Section III forms are verified through Mahony's own co-authored ACRA 2012 reproduction (Eq 23 explicitly cited to the RAM paper); Svacha RA-L 2020 is likewise closed, verified via RotorPy's published restatement; the archived Svacha ICUAS17 author PDF is truncated after p.3 (model section fully recovered, identified k_omega/k_z/k_h values lost). ### Lumped linear rotor-drag force (Faessler RA-L 2018 translational model) — already covered

- **Equations:** Eq (1)-(2): p_dot = v ; v_dot = -g*z_W + c*z_B - R*D*R^T*v. Frames/symbols: p, v = position/velocity of CoM in WORLD frame [m, m/s]; z_W = world vertical unit vector; z_B = body z (thrust) axis expressed in world coords; R = [x_B y_B z_B] in SO(3), body->world; c = mass-normalized collective thrust [m/s^2]; D = diag(d_x, d_y, d_z) = constant mass-normalized rotor-drag coefficient matrix, units [1/s] (so R*D*R^T*v is an acceleration). Stated assumptions (Sec. III): model from Kai et al. [10] with no wind, stiff propellers, and no dependence of rotor drag on thrust. The lumping that turns per-rotor -Omega_i*K*v_i forms into constant D is the near-hover assumption sqrt(T_i) ~= sqrt(mg/4) (made explicit in Kai et al. Sec 2.3), equivalently sum of rotor speeds ~= constant.
- **Source:** Faessler, Franchi, Scaramuzza, 'Differential Flatness of Quadrotor Dynamics Subject to Rotor Drag for Accurate Tracking of High-Speed Trajectories', IEEE RA-L 3(2), 2018, Eqs (1)-(2), Sec. III (verified from arXiv:1712.02402v3 PDF, p.2)
- **Parameters:** Identified on their FPV-racing quad (Sec. VI): d_x = 0.544 1/s, d_y = 0.386 1/s (circle trajectory); d_x = 0.491 1/s, d_y = 0.236 1/s (lemniscate); at 2.8 m/s: d_x = 0.425, d_y = 0.256 1/s. d_z: no measurable tracking improvement (they set d_z = 0), k_h = 0.009 1/m.
- **Relevance:** Baseline control-oriented drag model; useful for validating that the per-rotor model reduces to it near hover.
- **Notes:** The per-rotor H-force H_i = -Omega_i*diag(k_d,k_d,k_z)*v_i (rotorpy/vehicles/multirotor.py:348, matrix at :151-153) is the finer-grained parent model: summing over rotors with Sum(Omega_i) ~= const and rotating to world frame yields exactly -R*D*R^T*v with m*d_xy = k_d*Sum(Omega_i). Their D is constant (loses thrust/rotor-speed dependence); the per-rotor form retains it. Do not add both.

### Drag-induced angular-dynamics terms A*R^T*v and B*omega (Faessler eq 4) — already covered

- **Equations:** Eq (3)-(4): R_dot = R*omega_hat ; omega_dot = J^{-1}*(tau - omega x J*omega - tau_g - A*R^T*v - B*omega). Symbols: omega = body rates in BODY frame [rad/s]; J = inertia matrix [kg m^2]; tau = torque input [N m]; tau_g = propeller gyroscopic torques; A, B = constant matrices (from Kai et al. [10]): A*R^T*v = moment from airspeed [N m], B*omega = aerodynamic damping moment. Kai et al. give the explicit lumped forms: A = -C with C = -c12*[e3]_x, c12 = 2*e*sqrt(m*g)*(c_av + c_d1) (e = rotor-plane height above CoM [m]); damping D_mat = d11*pi_e3 + d33*e3*e3^T with d11 = 2*sqrt(m*g)*(e^2*(c_av+c_d1) + e*c_aOmega), d33 = 2*d^2*sqrt(m*g)*(c_av + c_d1) (d = arm length [m]); pi_e3 = I - e3*e3^T.
- **Source:** Faessler et al. RA-L 2018 Eq (4) + Kai, Allibert, Hua, Hamel, 'Nonlinear feedback control of Quadrotors exploiting First-Order Drag Effects', IFAC World Congress 2017, Eq (15) and constants below it (verified from hal.science/hal-01544740 PDF, p.4)
- **Relevance:** These moments are what makes rotor drag matter for attitude dynamics at speed.
- **Notes:** Coverage is structural in the per-rotor model rather than lumped: (a) the airspeed-moment (A-term) is the implemented flapping moment -k_flap*Omega_i*(v_i x z) at multirotor.py:351 (same direction: +k_flap*Omega*(e3 x v), matching +c12*(e3 x v_B) for rotors above CoM) plus r_i x H_i lever-arm moments at :361; (b) the yaw damping d33*e3e3^T*omega emerges automatically because local rotor airspeed includes omega x r_i (:338) and the resulting H_i is crossed with r_i (:361); (c) the roll/pitch damping d11*pi_e3*omega only appears if rotor_pos has a nonzero z-offset e (supported: rotor_pos is a full 3-vector, crazyflie_params.py:30-35, but all shipped params use z=0). If a vehicle has rotors meaningfully above/below the CoM, set the z-offset rather than adding a new term.

### Per-rotor H-force (induced/profile in-plane rotor drag), Kai et al. exact form — already covered

- **Equations:** Eq (6): F_drag_i = -sqrt(T_i)*c_d1*pi_e3*V_a^i, with V_a^i = R^T*v_a + Omega x d_i = translational air-velocity of rotor i in BODY frame [m/s]; d_i = rotor position w.r.t. CoM [m]; pi_e3 = I - e3*e3^T (projection onto rotor plane); T_i = c_T*omega_i^2 [N]; c_d1 > 0 constant [sqrt(N)*s/m]. Note sqrt(T_i) = sqrt(c_T)*|omega_i|, so F_drag_i = -sqrt(c_T)*c_d1*|omega_i|*pi_e3*V_a^i: exactly linear in rotor speed times in-plane local airspeed. NB their frame has e3 DOWN-ish ('e3^B opposite to thrust'); the physics is frame-symmetric.
- **Source:** Kai, Allibert, Hua, Hamel, IFAC 2017, Eq (6), Sec 2.1 (verified from HAL PDF p.3); attributed there to Prouty 2002 and Martin & Salaun ICRA 2010
- **Relevance:** This is the primary-literature justification for the per-rotor H-force being proportional to Omega_i * v_i including the omega x r lever-arm airspeed.
- **Notes:** Maps 1:1 to the x-y channel of H = -Omega_i*diag(k_d,k_d,k_z)*v_local_i at multirotor.py:348 with k_d = sqrt(c_T)*c_d1, and the local_airspeeds term (:338) equals their V_a^i. The z-channel (k_z) is NOT in Kai's model (pi_e3 kills it); its provenance is Svacha's inflow thrust correction (separate finding).

### Blade-flapping FORCE with lateral (sgn omega) and body-rate components — **ADOPTED (candidate tier)**

- **Equations:** Eq (10): F_flap_i = -sqrt(T_i)*c_av*pi_e3*V_a^i + sgn(omega_i)*sqrt(T_i)*c_bv*(e3 x V_a^i) - sgn(omega_i)*sqrt(T_i)*c_bOmega*pi_e3*Omega - sqrt(T_i)*c_aOmega*(e3 x Omega). Symbols: c_av, c_bv, c_aOmega, c_bOmega > 0 constants depending on blade aero/geometry; Omega = body rates [rad/s]; all in BODY frame [N]. Lumped force result (Eq 13): m*v_dot = m*g*e3 - T*R*e3 - R*A_lump*R^T*v_a - R*B_lump*Omega with A_lump = a11*pi_e3, a11 = 2*sqrt(m*g)*(c_d1 + c_av); B_lump = b12*[e3]_x, b12 = 2*sqrt(m*g)*(c_aOmega + e*c_a) [as printed; dimensional bookkeeping implies the e-term carries (c_d1+c_av)]. Kai remark (1) p.5: under sqrt(T_i) ~= sqrt(mg/4), all sgn(omega_i) terms cancel pairwise for counter-rotating rotors.
- **Source:** Kai et al. IFAC 2017, Eq (10) and Eqs (13),(15) with constants, Sec 2.2-2.3 (verified from HAL PDF p.4-5); flapping force model credited to Prouty 2002, Martin & Salaun 2010
- **Relevance:** Flapping tilts the thrust vector: it is a FORCE, not only a hub moment. The verified model represents flapping purely as a moment (k_flap), never as a force.
- **Notes:** Partial duplication: the c_av term has identical form to the H-force and is absorbed into k_d (Kai themselves lump them: a11 = 2*sqrt(mg)*(c_d1+c_av); remark 3 says separating flapping from drag parameters is 'hopeless'). Genuinely missing: (i) lateral side-force sgn(omega_i)*sqrt(T_i)*c_bv*(e3 x V_a^i) - cancels with balanced counter-rotating pairs, contributes under differential rotor speeds (i.e., during attitude transients); (ii) net body-rate force -R*B_lump*Omega (survives cancellation) - zero in this model since Sum(Omega x r_i) = 0 for symmetric geometry. Low-priority, cheap to add as per-rotor terms: F_i += sgn_i*k_bv*Omega_i*(z x v_i) - k_aOmega*Omega_i*(z x omega_body). Credible provenance (Prouty helicopter theory via Kai).

### Per-rotor rolling moment and rotor-plane damping moment (parasitic torque) — **ADOPTED (candidate tier)**

- **Equations:** Kai Eq (7) (rigid rotors): tau_a = Sum_i [ -sgn(omega_i)*sqrt(T_i)*c_d2*pi_e3*V_a^i - sqrt(T_i)*c_d3*pi_e3*Omega + d_i x F_drag_i ]. BODY frame [N m]. Term 1: pure rolling moment at the hub from lift dissymmetry between advancing/retreating blades, IN THE ROTOR PLANE, parallel to the in-plane airspeed, sign set by spin direction; c_d2 [sqrt(N)*m*s/m]. Term 2: rotor aerodynamic damping moment proportional to body rates; c_d3 [sqrt(N)*m*s]. Term 3: lever-arm moment of the H-force. For flexible rotors (Eq 11) the hub torques are absorbed into flapping and tau_a = Sum_i d_i x (F_flap_i + F_drag_i).
- **Source:** Kai et al. IFAC 2017, Eq (7) and Eq (11) (verified from HAL PDF p.3-4)
- **Relevance:** The c_d2 rolling moment is a hub moment missing entirely; the k_flap moment is perpendicular to the airspeed (v x z) whereas c_d2 is parallel to pi_e3*v — different axis, different physics (rigid-blade lift dissymmetry transmitted to the frame).
- **Notes:** Term 3 is present exactly (multirotor.py:361) and an analog of the flexible-rotor hub moment via k_flap (:351). Missing: term 1 (sgn-dependent, cancels at balanced rotor speeds — matters during yaw-mixing/differential thrust) and term 2's in-plane part (roll/pitch aero damping; only its yaw component emerges from the omega x r_i lever-arm path). Suggested per-rotor forms consistent with the existing terms: M_i += -sgn_i*k_roll*Omega_i*pi_z*v_i - k_damp*Omega_i*pi_z*omega_body. For the JAX port these are two more diagonal-style gains, fully differentiable.

### Induced drag, world-frame lumped, with sum-of-rotor-speeds scaling (Svacha ICUAS 2017) — already covered

- **Equations:** Eq (1): D = -k_d*omega_s*R*P*R^T*V, with V = CoM velocity in WORLD frame [m/s]; omega_s = Sum_{i=1..4} omega_i (sum of motor speeds); P = diag(1,1,0) (body x-y projection); R body->world. Frames: W = NWU (x North, y West, z up), B = FLU (x fwd, y left, z up). Eq (2): V_dot = (F/m)*R*e3 - g*e3 - (k_d/m)*omega_s*R*P*R^T*V. Eq (3): Omega_dot = J^{-1}( -Omega x J*Omega + M + (-k_d*omega_s*P*R^T*V) x h*e3 ), i.e. the drag force (body frame) crossed with the propeller-plane offset h*e3, h = height of propellers above CoM [m].
- **Source:** Svacha, Mohta, Kumar, 'Improving Quadrotor Trajectory Tracking by Compensating for Aerodynamic Effects', ICUAS 2017, Eqs (1)-(3), Sec II-A (verified from author PDF via Wayback: web.archive.org/web/20190920080717/http://jamessvacha.com/ICUAS17.pdf; note archived copy truncated after p.3, model section fully recovered)
- **Parameters:** Identified k_d = 1.314e-5 N*s/(m*RPM) (R^2 = 0.975, Penn quad, forward flight 0-8 m/s). In rad/s units: 1.255e-4 N*s^2/(rad*m).
- **Relevance:** Direct ancestor of the per-rotor H-force x-y channel; also documents the drag MOMENT via prop-plane height h.
- **Notes:** The per-rotor form -Omega_i*k_d*v_i summed equals their -k_d*omega_s*P*v_B when all rotors see the CoM airspeed; the per-rotor version additionally resolves per-rotor omega x r_i airspeed. Their h*e3 lever-arm moment = the r_i x H_i term with a z-offset in rotor_pos (currently 0 in all shipped params — set it for vehicles with tall prop stacks instead of tuning k_flap to compensate). Unit-comment nits in the rotorpy tree: multirotor.py:132-135 says 'N/(m/s)' and crazyflie_params.py:50-53 says 'N/(rad*m/s**2) = kg/rad'; the dimensionally correct unit for k_d, k_z is N/((rad/s)*(m/s)) = kg*s/rad, and for k_flap is N*m/((rad/s)*(m/s)) = kg*m*s/rad.

### Refined BEMT thrust model with induced-inflow correction (source of k_z and k_h) — already covered

- **Equations:** Eq (4): T_i = c1*omega_i^2*( c2*(1 + (3/2)*mu_i^2) - lambda_i ), with advance ratio mu_i = (V_hi + v_hi)/(r*omega_i), inflow ratio lambda_i = (V_zi + v_zi)/(r*omega_i); r = prop radius [m]; V_hi, V_zi = horizontal/vertical components of rotor i's velocity in BODY frame [m/s]; v_hi, v_zi = induced velocity components. Momentum theory (Eq 7): T_i = 2*rho*A*v_i*(v_i + V_z), A = pi*r^2. Empirical induced-velocity fit (Eq 8): v_i(omega_i, V_zi) = a*omega_i - b*V_zi (linear fit, adjusted R^2 = 0.974). Final refined model (Eq 9): T_i = k_omega*omega_i^2 - k_z*V_zi*omega_i + k_h*V_hi^2, k_omega, k_z, k_h > 0 identified constants. Units: k_omega [N*s^2/rad^2], k_z [N*s^2/(rad*m)], k_h [N*s^2/m^2 = kg/m].
- **Source:** Svacha, Mohta, Kumar, ICUAS 2017, Eqs (4)-(9), Sec II-B (verified from archived author PDF, p.2-3)
- **Relevance:** Exact provenance of the spec's k_z (induced-inflow thrust loss, linear in Omega_i*v_z) and k_h (translational lift, quadratic in in-plane speed).
- **Notes:** The implementation matches term-for-term: -k_z*Omega_i*v_z_local is the z-row of the rotor drag matrix (multirotor.py:348, matrix :151-153) — sign correct with z-up (climb reduces net upward force); +k_h*(vx_i^2+vy_i^2) added to thrust magnitude at :353 uses per-rotor local airspeed = their V_hi^2. RotorPy paper footnote 2 (arXiv:2306.04485) states explicitly that k_z 'isn't actually a source of drag, but a linear approximation of loss of thrust due to change in inflow' — same interpretation. The spec's k_angle/k_hor multiplicative correction (aoa_thrust_factor, identified by SkyDreamer) is a competing parameterization of the same mu/lambda physics — the mutual exclusion against combining k_h with k_angle/k_hor noted on those spec terms is well-founded; arguably k_z should also be zeroed when k_angle is active (both linearize lambda dependence).

### Body-frame velocity dynamics with diag(kd,kd,kz) drag matrix (Svacha RA-L 2019) and flapping moment -k_flap*Omega*(v x z) (Svacha RA-L 2020 via RotorPy) — already covered

- **Equations:** Svacha RA-L 2019 Eq (14): v_dot = (k_f/m)*u_ss*e3 - (u_s/m)*D*v - g*Rz(pi)*z - omega x v + noise, BODY frame; u_ss = Sum(u_i^2), u_s = Sum(u_i) (motor speeds); D = diag(k_d, k_d, k_z); z = tilt (direction of b3) on S^2; measurement Eq (16): y2 = (k_f/m)*u_ss*e3 - (u_s/m)*D*v + b_a. RotorPy paper (adopting Svacha RA-L 2020 [their ref 6]) Eq (8): D_ri = -K*eta_i*v_ai with K = diag(k_d, k_d, k_z); Eq (9): m_flap_i = -k_flap*eta_i*(v_ai x b3); total: f_a = D_p + Sum_i D_ri, m_a = Sum_i (m_flap_i + r_i x D_ri). Symbols: eta_i = rotor speed [rad/s], v_ai = rotor-local body airspeed incl. omega x r_i [m/s], b3 = body z axis.
- **Source:** Svacha, Loianno, Kumar, 'Inertial Yaw-Independent Velocity and Attitude Estimation for High-Speed Quadrotor Flight', RA-L 2019, Eqs (14),(16) (verified from archived author PDF: web.archive.org/web/20190920081401/http://jamessvacha.com/RAL19.pdf); Svacha, Paulos, Loianno, Kumar, 'IMU-Based Inertia Estimation for a Quadrotor Using Newton-Euler Dynamics', RA-L 5(3) 2020 (paywalled; exact adopted forms verified via Folk et al., 'RotorPy: A Python-based Multirotor Simulator...', arXiv:2306.04485, Eqs (8)-(9) and refs [6],[7])
- **Relevance:** This is the literal, direct provenance chain of the H-force and k_flap implementation (RotorPy inherited it from Svacha 2020).
- **Notes:** multirotor.py:348 (H-force) and :351 (M_flap) reproduce RotorPy paper Eqs (8)-(9) exactly, including the per-rotor lever arm r_i x D_ri (:361). Sign check for M_flap: forward flight v=+x gives -k_flap*Omega*(x cross z) = +k_flap*Omega*y = pitch-up, the correct tip-path-plane-tilts-back response. The RA-L 2020 full text was not accessible anywhere legitimate (IEEE closed, no arXiv/NSF-PAR/author copy); confidence in the exact form rests on RotorPy's published restatement plus consistency with RAL19/ICUAS17 — flag if byte-exact fidelity to the 2020 paper ever matters.

### Mahony-Kumar-Corke 2012 (RAM): static thrust/torque and lumped blade-flapping + induced-drag model — already covered

- **Equations:** As reproduced with explicit citation by co-author Bangura: static rotor models T_i = C_T*varpi_i^2, tau_zi = C_Q*varpi_i^2 ('those used in thrust and torque models presented in Mahony [Mahony et al., 2012]'); lumped flapping/induced-drag force per rotor (Bangura Eq 23, cited '[Mahony et al., 2012]'): Delta_i = T_i*( A_flap*(V_pi/varpi_i) + B_flap*(Omega/varpi_i) ), with A_flap = (1/r)*[[-A1c, A1s, 0], [-A1s, -A1c, 0], [0,0,0]] and B_flap = [[-B2, B1, 0], [B1, -B2, 0], [0,0,0]]; V_pi = (Vx,Vy,0)^T of rotor i in BODY frame [m/s]; varpi_i = rotor speed [rad/s]; A1c, A1s from flapping-angle solution beta(psi) = beta_0 + beta_c*cos(psi) + beta_s*sin(psi) with beta_c = -(|Vp|/(varpi*r))*A1c - B2*Omega_1/varpi + B1*Omega_2/varpi, beta_s = -(|Vp|/(varpi*r))*A1s + B1*Omega_1/varpi - B2*Omega_2/varpi (small-mu simplification of Pounds 2007 / Leishman Eqs 4.45, 4.47). Since T_i/varpi_i = C_T*varpi_i, the diagonal of Delta_i is linear in rotor speed x in-plane airspeed — identical family to the H-force. Faessler (RA-L 2018, p.2) cites this paper [their ref 6] for: blade flapping and induced drag 'thanks to their equivalent mathematical expression, typically combined as linear effects in a lumped parameter dynamical model'.
- **Source:** Mahony, Kumar, Corke, 'Multirotor Aerial Vehicles: Modeling, Estimation, and Control of Quadrotor', IEEE Robotics & Automation Magazine 19(3):20-32, 2012, Section III — DIRECT TEXT NOT ACCESSIBLE (IEEE paywall; ANU repository restricted until 2037; QUT ePrints no fulltext). Equations verified via co-author reproduction: Bangura & Mahony, ACRA 2012, Sec 3.2 and Eqs (16)-(23) (open PDF, ANU repository bitstream 444eb90e-4506-40d5-9984-fc2e9a48c75c)
- **Relevance:** The canonical citation for lumping flapping + induced drag as one linear-in-velocity effect; validates treating k_d as a combined coefficient rather than adding a second flapping force.
- **Notes:** Diagonal (-A1c) part of Delta_i duplicates the k_d H-force. What the model drops relative to the full Mahony/Pounds form: (i) the OFF-DIAGONAL A1s terms (lateral flapping force perpendicular to airspeed — same physics as Kai's c_bv side-force; cancels for balanced counter-rotating pairs), and (ii) B_flap*(Omega/varpi_i)*T_i (flapping force from body rates — same as Kai's B-matrix). These are covered by the Kai adopt-candidate findings; do not double-adopt. Skepticism note: because the RAM 2012 text itself was unreachable, equation numbering within the magazine article is unconfirmed; the forms above carry Mahony's own co-authorship in the ACRA 2012 reproduction, which is the strongest available provenance.

### Momentum-theory thrust with induced velocity in oblique flight (nonlinear T(V) correction) — **ADOPTED (candidate tier)**

- **Equations:** Bangura & Mahony Eqs (10a),(10b),(11): T_i = 2*rho*A*v_ii*U_i ; P_ai = 2*rho*A*v_ii*U_i*(v_ii - V_zi) ; U_i = sqrt( V_xi^2 + V_yi^2 + (-V_zi + v_ii)^2 ). Symbols: rho = air density [kg/m^3]; A = pi*r^2 rotor disc area [m^2]; v_ii = induced velocity through rotor i [m/s], positive UP; V_i = (V_xi,V_yi,V_zi) = rotor i's velocity in BODY frame incl. Omega x lever arm (V_1 = V + Omega x [d*e1 - h*e3], etc.), with their z POSITIVE DOWN (paper notes the sign convention explicitly); P_ai = aerodynamic power = FoM*P_mi. Given power (or given omega with T_i = C_T*varpi_i^2 as the hover limit), solve (10b)+(11) for v_ii by Newton iteration, then (10a) gives thrust. Hover limit: U_i = v_ii = v_h = sqrt(T_i/(2*rho*A)), recovering T_i = C_T*varpi_i^2. Generalization (Bangura et al. monograph, p.10): v_iz^0 = T/(2*rho*A*|V_a|), Glauert distribution v_iz = v_iz^0*(1 + kappa_e*(r/R)*cos(psi)), P = T*(kappa_e*v_iz - V_z) + H*(kappa_e*v_ih + V_h).
- **Source:** Bangura & Mahony, 'Nonlinear Dynamic Modeling for High Performance Control of a Quadrotor', ACRA 2012, Eqs (10a)-(11) and Sec 3.5 (verified from ANU open-access PDF); corroborated by Bangura, Melega, Naldi, Mahony, 'Aerodynamics of Rotor Blades for Quadrotors', arXiv:1601.00733, Sec 2
- **Relevance:** The full nonlinear thrust-vs-airspeed law. The verified inventory only has linearizations of it: k_z*Omega*v_z (linear inflow), k_h*v_h^2 (translational lift), k_angle/k_hor*atan2 corrections, k_v2*vz*|vz|. Under fast climb/descent or high advance ratio these diverge from the implicit momentum-theory solution.
- **Notes:** Implementable as an optional per-rotor thrust correction: solve the quartic 2*rho*A*v_i*sqrt(V_h^2 + (v_i - V_zup)^2) = C_T*varpi_i^2-consistent power balance for v_i (2-3 Newton steps, differentiable via implicit function theorem — good fit for the planned JAX port). Would supersede k_z/k_h/k_angle/k_v2 when enabled (config guard needed to avoid double counting, mirroring the k_h vs k_angle mutual exclusion noted on the spec terms).

### Vortex Ring State / Turbulent Wake State / Windmill Brake State boundaries (descent-regime hybrid model) — **ADOPTED (candidate tier)**

- **Equations:** Bangura & Mahony Sec 5.2 (prose thresholds, v_h = hover induced velocity = sqrt(T/(2*rho*A)) [m/s], descent rate = -V_z_up): VRS onset when rate of descent = 0.5*v_h (momentum theory INVALID; high vibration, uncommanded pitch/roll); TWS when rate of descent = v_i (no net flow through disc, momentum theory predicts no thrust); WBS when rate of descent > 2*v_h, where momentum theory again applies with T_i = -2*rho*A*(-V_zi + v_ii)*v_ii (their z-down sign convention). Monograph (arXiv:1601.00733 p.10) states the same VRS boundary: 'rate of descent is half the vertical induced velocity'.
- **Source:** Bangura & Mahony, ACRA 2012, Sec 5.2 (verified from ANU PDF, p.8); Bangura et al. arXiv:1601.00733 Sec 2.6
- **Relevance:** Defines the validity envelope of every thrust model in the spec during descent. A simulator used for RL on aggressive descents will silently extrapolate the quadratic thrust curve into a regime where the physics (and the momentum-theory correction above) are wrong.
- **Notes:** Minimum viable adoption: compute per-rotor v_h and flag/penalize (or add stochastic disturbance in) the band -2*v_h < V_z_climb < -0.5*v_h; full adoption = hybrid model switching to the WBS branch below -2*v_h. Bangura gives no smooth interpolation inside VRS/TWS (none exists from momentum theory) — empirical fills (e.g. Johnson's curve fits) would be a separate source if smoothness is needed.

### Ground effect (Cheeseman-Bennett) thrust ratio — **ADOPTED (candidate tier)**

- **Equations:** Bangura & Mahony Eq (31): T_g/T_inf = 1 / ( 1 - (r/(4*|z|))^2 * 1/(1 + (|V|/v_i)^2) ), where |z| = rotor height above ground [m], r = rotor radius [m], |V| = airspeed magnitude [m/s], v_i = induced velocity [m/s]; T_g, T_inf = thrust in/out of ground cushion at constant power. Effect negligible once r/|z| < 0.1 (their stated cutoff; note as printed — the intended reading is |z| > ~2.5r given the (r/4|z|)^2 form).
- **Source:** Bangura & Mahony, ACRA 2012, Eq (31), Sec 5.1 (verified from ANU PDF, p.8), original: Cheeseman & Bennett 1957
- **Relevance:** Ground contact force is modeled (multirotor.py `_handle_vehicle_on_ground`) but not the aerodynamic thrust increase near ground; matters for takeoff/landing RL tasks.
- **Notes:** One-line multiplicative thrust correction gated on _enable_ground; needs rotor height = x_z + rotor_pos z-offset. Per-rotor application is straightforward and differentiable.

### Bangura drag taxonomy: induced + translational + profile (linear, rotor-speed-independent) and high-speed quartic factor — already covered

- **Equations:** Sec 4.2-4.6, BODY frame, V_p = (Vx,Vy,0)^T [m/s]: induced drag D_I = K_I*V_p; translational (momentum) drag D_T = K_T1*V_p (low speed) or D_T = K_T2*(-V_z + v_i)^4*V_p (high speed, V_p > w); profile drag D_p = rho*c*(c_d0 + c_dalpha*theta_0)*(varpi*r^2 - (-V_z + v_i)*r)*V_p, lumped D_p = K_p*V_p; parasitic D_par = K_par*|V|*V with K_par = (1/2)*rho*S*C_Dpar; low-speed total per rotor (Eq 27): D_i = D_K*V_pi + T_i*A_flap*V_pi/varpi_i + T_i*B_flap*Omega/varpi_i, D_K = K_I + K_T + K_p; total (Eq 28): D_b = Sum_i D_i + K_par*|V|*V; drag torques (Eq 30 block): tau_D1 = D_1 x [d*e1 - h*e3], etc., tau_D = Sum tau_Di. Units: K's in N/(m/s) except K_T2 [N*s^5/m^5], K_par [N/(m/s)^2].
- **Source:** Bangura & Mahony, ACRA 2012, Secs 4.2-4.6, Eqs (24)-(30) (verified from ANU PDF, p.6-8)
- **Relevance:** Cross-check of the drag decomposition; documents that part of the linear in-plane drag (K_I, K_T1, K_p) is rotor-speed-INDEPENDENT in their lumping, unlike the purely Omega-proportional H-force.
- **Notes:** Parasitic term == the parasitic drag -|v|*diag(cD)*v (multirotor.py:346). The linear channel: near hover varpi ~ const, so K*V_p and k_d*Omega*V_p are observationally equivalent — adding a separate constant-linear-drag channel would double count against identified k_d values; skip unless fitting data spanning large thrust ranges (then a two-term a0 + a1*Omega in-plane drag is the principled extension). The high-speed (-V_z + v_i)^4 translational-drag factor and the profile-drag dependence on (varpi*r^2 - (-V_z+v_i)*r) are genuinely absent from the model but Bangura provides no identified constants and flags w as rotor-specific — weak provenance for adoption as-is.

### BET closed-form H-force (theoretical basis for H proportional to Omega * v_horizontal) — already covered

- **Equations:** Monograph Eqs (56),(58),(59): profile part H_p = (1/4)*rho*N_b*c*C_d*R^3*mu*varpi^2; induced part H_i = (1/4)*N_b*rho*C_lalpha*c*R^3*varpi^2*[theta_0*(lambda*mu + a1/3) - lambda*a1 + a1*lambda/2 - a1*theta_0/3] (flapping-coefficient products dropped); total with theta_0^2 ~ 0: H = (1/4)*N_b*rho*C_lalpha*c*R^3*varpi^2*mu*[ C_d/C_lalpha - (1/3)*theta_0*lambda + lambda^2 ]. Symbols: N_b = blade count; c = chord [m]; R = rotor radius [m]; C_lalpha = lift slope [1/rad]; C_d = drag coeff; theta_0 = collective pitch [rad]; mu = |V_p|/(varpi*R) advance ratio; lambda = inflow ratio. Since mu*varpi^2 = |V_p|*varpi/R, H is linear in (rotor speed x in-plane airspeed). Text: 'In the current quadrotor literature, a linear relation H proportional to T has been proposed in [2,13]'; 'For very rigid blades the flapping coefficients a0,a1,b1 are very small resulting in a very small H_i.'
- **Source:** Bangura, Melega, Naldi, Mahony, 'Aerodynamics of Rotor Blades for Quadrotors', arXiv:1601.00733, Eqs (55)-(59) (verified from arXiv PDF, p.23-24)
- **Relevance:** First-principles confirmation that the per-rotor H = -k_d*Omega_i*v_xy has the correct functional form, and gives k_d's physical composition: k_d = (1/4)*N_b*rho*C_lalpha*c*R^2*(C_d/C_lalpha - theta_0*lambda/3 + lambda^2) — a route to computing k_d from prop geometry instead of flight-test fits.
- **Notes:** Useful for domain randomization priors and for the JAX port's parameter documentation; no new dynamics term.

### Rotor gyroscopic torque and motor electrical/power model (Bangura) — already covered

- **Equations:** Gyroscopic (Eq 5): G_a = -Sum_{i=1..4} (-1)^{i+1} * Omega x (I_r * varpi_vec_i), varpi_vec_i = (0,0,varpi_i)^T, I_r = rotor inertia [kg m^2], BODY frame [N m]. Motor electrical (Eqs 6a,6b,7): V_ai = K_e*varpi_i + R_a*i_ai ; tau_zi = K_q*i_ai ; P_mi = (K_q*varpi_i/R_a)*(V_ai - K_e*varpi_i); PWM_i = (V_ai/V_source)^2; FoM = P_ai/P_mi (Eq 8).
- **Source:** Bangura & Mahony, ACRA 2012, Eqs (5)-(8) (verified from ANU PDF, p.3); parameters Table 1
- **Parameters:** Their quad: K_q = 0.0099375 N m/A, K_e = 0.0013 V s/rad, R_a = 0.5033 Ohm, FoM = 0.67483, C_T = 1.536e-7 N/RPM^2 (fit in RPM), kappa = C_T/C_Q = 79.066
- **Relevance:** Gyroscopic term: identical physics to the spec's. Electrical model: alternative power-as-input abstraction; also gives battery current draw i_ai = P_mi/(K_q*varpi_i) for energy simulation.
- **Notes:** G_a == the spec's rotor_inertia_moment gyroscopic part, which additionally carries the reaction torque -I_r*Sum(spin_i*Omega_dot_i) that Bangura omits here. The electrical/power model is out of the rotor-drag scope; if battery energy/current simulation is ever wanted, this is the credible source (mark that sub-piece as a possible future adopt, not now).

### Faessler thrust input model c = c_cmd + k_h*v_h^2 and the d_z lumping statement — already covered

- **Equations:** Eq (5): c = c_cmd + k_h*v_h^2 with v_h = v^T*(x_B + y_B) — NOTE: as printed, v_h is the SUM of the body-x and body-y velocity components (so v_h^2 includes a 2*vx*vy cross term and is not rotation-invariant in the plane), unlike Svacha's original k_h*V_hi^2 with V_hi = norm of the in-plane velocity. Accompanying statement: 'The additional linear velocity-dependent disturbance in the z_B direction of the thrust model in [12] is lumped by d_z directly in (2) by neglecting its dependency on the rotor speeds' — i.e., their d_z IS Svacha's k_z with Sum(omega_i) frozen.
- **Source:** Faessler et al., RA-L 2018, Eq (5) and following paragraph, Sec III (verified from arXiv:1712.02402v3 PDF, p.2)
- **Relevance:** Documents exactly how the per-rotor -Omega_i*K*v_i z-channel degenerates into the constant d_z of the lumped model, and flags a form discrepancy in the k_h term between the two papers.
- **Notes:** The implemented k_h at multirotor.py:353 follows Svacha's (vx^2 + vy^2) form, which is the physically sensible rotation-invariant one; keep it and do not switch to Faessler's printed (vx+vy)^2. Their experiments found k_h = 0.009 1/m mattering an order of magnitude less than d_x, d_y — consistent with treating k_h as a small correction.

### Generic per-rotor wrench and design taxonomy (Hamandi et al. 2021) — already covered

- **Equations:** Eq (1): f_Pi = c_fi*|w_i|*w_i*v_i ; m_Pi = k_i*c_tau_i*|w_i|*w_i*v_i, applied at rotor position O_Pi, expressed in BODY frame; v_i = unit rotor thrust axis (arbitrary orientation, parametrized by fixed or actuated tilt angles alpha_i, beta_i); w_i = signed rotor angular rate [rad/s] (|w|*w preserves sign for bidirectional propellers); k_i in {-1,+1} spin handedness; c_fi [N s^2/rad^2], c_tau_i [N m s^2/rad^2]. - **Source:** Hamandi, Usai, Sablé, Staub, Tognon, Franchi, 'Design of Multirotor Aerial Vehicles: a Taxonomy Based on Input Allocation', IJRR 40(8-9), 2021, Eq (1), Sec 2 (verified from HAL PDF hal-02433405v2, p.3-4)
- **Relevance:** Checked for anything the drag/flapping sources missed: nothing aerodynamic — the paper's content is actuation geometry and allocation (underactuated/omnidirectional, fixed/variable tilt), not aero modeling.
- **Notes:** Per-rotor arbitrary thrust axis v_i == the spec's thrust_axis_misalignment term (per-rotor axis with full force/moment bookkeeping); this entry is its cited provenance. Only nuance missing: the signed |w|*w form for BIDIRECTIONAL (reversible) props — the polynomial thrust curve assumes w >= 0. Skip unless reversible-thrust vehicles enter scope.


## Simulator survey (RotorS, PX4 SITL, Flightmare, Agilicious, MuJoCo)

Surveyed RotorS (source + firefly xacro), PX4 SITL gazebo-classic (source + header defaults + iris model), Flightmare (quadrotor_dynamics.cpp), Agilicious (public repo is docs-only; used official docs + the NeuroBEM RSS 2021 paper it cites), and MuJoCo menagerie drones + MuJoCo fluid docs. Most of what these simulators model duplicates the spec's inventory — Flightmare and the menagerie models are strict subsets, and RotorS/PX4 rotor drag, drag torque, asymmetric motor filter, and thrust-vs-axial-airspeed decay are all already covered. Three genuine gaps surfaced: (1) the RotorS/PX4 rolling moment -|omega|*d_i*mu_R*v_perp, a blade-flapping torque component PARALLEL to the perpendicular airspeed that complements the spec's existing -kflap*W*(v x z) term (default mu_R = 1e-6 across all vehicles; note RotorS omits the turning-direction sign, PX4 includes it and is the physically defensible form); (2) the full BEM per-rotor model from NeuroBEM/Agilicious (eqs 5-19: momentum-theory induced-velocity fixed point, blade-element integrals for T/H/Q, hinge-spring flapping angles, and an empirical quartic vortex-ring-state correction for descent) — the only surveyed model adding physics the spec lacks entirely (inflow coupling, vortex ring state), suitable as an optional high-fidelity rotor model and differentiable via implicit differentiation for the JAX port; (3) aerodynamic angular-rate damping torque from MuJoCo's inertia-based fluid model (quadratic -(1/2) rho r_i (r_j^4+r_k^4)|omega_i|omega_i plus Stokes -8 beta pi r_eq^3 omega_i), absent from the spec's inventory in any form. Agilicious's ModelLinCubDrag exists but its exact equation is not publicly verifiable and is spanned by the spec's linear+quadratic drag; MuJoCo's ellipsoid added-mass/Magnus/Kutta model is negligible for dense small multirotors and unused by the menagerie drones.

### RotorS per-rotor 'air drag' (rotor drag / H-force) — already covered

- **Equations:** F_drag,i = -|omega_i| * c_D * v_perp, where v_perp = v_A - (v_A . a_i) a_i; v_A = v_link - v_wind is relative air velocity of the rotor link in Gazebo WORLD frame [m/s]; a_i = rotor joint axis unit vector (world frame); omega_i = rotor angular speed [rad/s] (code uses real_motor_velocity = motor_rot_vel * rotor_velocity_slowdown_sim); c_D = rotor_drag_coefficient with implied units kg/rad (so N = (rad/s)*(kg/rad)*(m/s)). Force applied at the rotor link (so it also produces a moment about CoM via the lever arm).
- **Source:** ethz-asl/rotors_simulator, rotors_gazebo_plugins/src/gazebo_motor_model.cpp, ~lines 393-400 (read via raw.githubusercontent.com; line numbers approximate). Model documented in Furrer et al., 'RotorS - A Modular Gazebo MAV Simulator Framework', 2016.
- **Parameters:** Firefly (rotors_description/urdf/firefly.xacro): rotor_drag_coefficient = 8.06428e-05; PX4 iris: 1.75e-04; PX4 code default kDefaultRotorDragCoefficient = 1.0e-4.
- **Relevance:** Identical in structure to rotorpy's per-rotor rotor-drag H-force -W*diag(kd,kd,kz)*v_local including lever arm; RotorS only damps the perpendicular component (kz equivalent = 0).
- **Notes:** rotorpy's version is a strict superset (adds axial kz term and w x r contribution to local velocity).

### RotorS/PX4 rolling moment (blade-flapping moment along v_perp) — **ADOPTED (candidate tier)**

- **Equations:** RotorS: M_roll,i = -|omega_i| * mu_R * v_perp (a TORQUE vector parallel to the perpendicular relative air velocity, world frame, applied to the base link via AddTorque). PX4 variant adds spin direction: M_roll,i = -|omega_i| * d_i * mu_R * v_perp, d_i in {+1 CCW, -1 CW}. Symbols: omega_i rotor speed [rad/s]; v_perp = (v_body - v_wind) minus component along rotor axis [m/s], world frame; mu_R = rolling_moment_coefficient, implied units kg*m/rad (N*m = (rad/s)*(kg*m/rad)*(m/s)).
- **Source:** ethz-asl/rotors_simulator rotors_gazebo_plugins/src/gazebo_motor_model.cpp ~lines 416-419 (no turning_direction factor); PX4/PX4-SITL_gazebo-classic src/gazebo_motor_model.cpp ~lines 149-151 (includes turning_direction_). Underlying physics (advancing/retreating blade lift asymmetry) per RotorS chapter, Furrer et al. 2016.
- **Parameters:** rolling_moment_coefficient = 1e-06 in RotorS firefly.xacro, PX4 iris.sdf.jinja, and PX4 header default kDefaultRollingMomentCoefficient = 1.0e-6 (all vehicles).
- **Relevance:** The spec's inventory has a blade-flapping moment -kflap*W*(v x z), i.e. a torque PERPENDICULAR to horizontal velocity. RotorS/PX4 apply the flapping moment PARALLEL to v_perp — a different axis of the same physical effect (longitudinal vs lateral flapping component). The two together span the full flapping moment plane; the spec currently models only one axis.
- **Notes:** Be aware of the RotorS/PX4 discrepancy: RotorS omits the turning-direction sign so all four rotors' moments add coherently; PX4 includes d_i so CW/CCW contributions partially cancel. Physically the advancing side flips with spin direction, so the PX4 form is the defensible one. Cheap to add: one coefficient per rotor, linear in v — JAX-friendly.

### RotorS/PX4 asymmetric first-order motor filter — already covered

- **Equations:** Reference rotor speed filtered before being applied: omega_ref_filtered = FirstOrderFilter(omega_cmd, dt) with separate time constants tau_up (accelerating) and tau_down (decelerating); discrete update uses alpha = exp(-dt/tau) exponential form. Filtered variable is the commanded rotor angular velocity [rad/s].

### RotorS/PX4 IMU stochastic error model (Gauss–Markov bias + white noise + turn-on bias) — **ADOPTED (candidate tier, 2026-08-20)**

- **Equations:** Per axis, per triad (gyro/accel with separate parameters): bias update b_{k+1} = phi_d*b_k + sigma_b_d*w_k with phi_d = exp(-dt/tau) and sigma_b_d = sqrt(-sigma_b^2*tau/2*(exp(-2*dt/tau) - 1)) — the exact discretization of the Ornstein–Uhlenbeck process ḃ = -b/tau + sigma_b*ẇ (code comment cites "Maybeck 4-114"); measurement y = y_true + b_k + sigma_d*n_k + b_on with sigma_d = sigma_nd/sqrt(dt) ("integrating sampler" convention) and b_on ~ N(0, sigma_on²) drawn once at init. Symbols: tau = bias correlation time [s]; sigma_b = bias random walk [unit·√Hz/s... as coded]; sigma_nd = noise density [unit/√Hz]; w_k, n_k ~ N(0,1).
- **Source:** ethz-asl/rotors_simulator rotors_gazebo_plugins/src/gazebo_imu_plugin.cpp lines 213–265 (AddNoise, read verbatim from raw source 2026-08-20); defaults in include/rotors_gazebo_plugins/gazebo_imu_plugin.h lines 39–55; PX4-SITL_gazebo-classic carries the same plugin. The Maybeck Vol. 1 Eq. 4-114 citation is the code's own; the book was not directly consulted — exactness is instead proven symbolically (properties/test_candidates.py: exact-exp transition, stationary-variance fixed point σ_b²τ/2, random-walk limits).
- **Parameters:** ADIS16448-based defaults, each shipped at 2× the datasheet figure: gyro sigma_nd = 2·35/3600·(π/180) ≈ 3.39e-4 rad/s/√Hz, sigma_b = 2·4/3600·(π/180) ≈ 3.88e-5, tau = 1000 s, sigma_on = 0.5°·(π/180) ≈ 8.73e-3 rad/s; accel sigma_nd = 4.0e-3 m/s²/√Hz, sigma_b = 6.0e-3, tau = 300 s, sigma_on = 0.196 m/s².
- **Relevance:** The standard executed IMU-corruption model of the ROS/Gazebo ecosystem; composes with the spec's deterministic imu term (specific force + lever arm) into a complete sensor model. ### BEM per-rotor propeller model (Agilicious high-fidelity option / NeuroBEM) — **ADOPTED (candidate tier)**

- **Equations:** All in propeller frame P (z_P down, x_P opposing horizontal inflow v_hor); rho = air density [kg/m^3], A = pi R^2 rotor disk area, R = rotor radius [m], Omega = rotor speed [rad/s], b = blade count, c(r) = chord [m], v_i = induced velocity [m/s], v_hor/v_ver = horizontal/vertical relative air velocity [m/s]. Momentum theory (eq 5): T = 2 v_i rho A sqrt(v_hor^2 + (v_ver - v_i)^2). Blade-element velocities (eqs 6-7): U_T(r,Psi) = Omega r + v_hor sin(Psi); U_P(r,Psi) = v_ver - v_i - r Omega (a1 sin Psi + b1 cos Psi) + v_ver (a0 - a1 cos Psi - b1 sin Psi) cos Psi, with a0 = coning, a1/b1 = longitudinal/lateral flapping angles, Psi = blade azimuth. Angles (eqs 8-9): phi = arctan(U_P/U_T); alpha = theta0 + (r/R) theta1 + phi (theta0 = blade pitch, theta1 = twist). Element forces (eqs 10-12): dL = c(r) c_l(alpha) (U_T^2 + U_P^2), dD = c(r) c_d(alpha) (U_T^2 + U_P^2), with c_l(alpha) = c_l0 sin(alpha) cos(alpha), c_d(alpha) = c_d0 sin^2(alpha) (c_l0, c_d0 from thrust-stand fits). Integrals (eqs 13-15): T = (b rho / 4 pi) int_0^R int_0^2pi (dL cos phi + dD sin phi) dPsi dr; H = (b rho / 4 pi) int int (-dL sin phi + dD cos phi) sin Psi dPsi dr; Q = (b rho / 4 pi) int int (-dL sin phi + dD cos phi) r dPsi dr. Flapping from hinge-spring moment equilibrium (eqs 16-17): 0 = M_w + M_gyro + M_inertial + M_cf + M_aero + M_spring, M_spring = k_beta (a0 + a1 cos Psi + b1 sin Psi), k_beta = torsional spring stiffness [N*m/rad] at hinge offset e. Vortex-ring state (eq 18): momentum theory invalid iff 0 < v_P,z / v_i < 2; then empirical quartic (eq 19): v_i_tilde = v_h,i [1 + 1.125 x - 1.372 x^2 + 1.718 x^3 - 0.655 x^4], x = v_P,z / v_h,i, v_h,i = induced velocity at v_P,z = 0; final v_i = max(v_i_tilde, v_h,i). Algorithm: (1) set a0=a1=b1=0; (2) solve v_i so eq 5 == eq 13 (fixed point), using eq 19 inside vortex-ring state; (3) compute a0, a1, b1; (4) re-evaluate eqs 13-15; (5) f_P = [-(H + sin(a1) T), +/- sin(b1) T, -T cos(a0)], tau_P = [+/- k_beta b1, k_beta a1, -/+ Q] (upper sign = CW propeller).
- **Source:** Bauersfeld, Kaufmann, Foehn, Sun, Scaramuzza, 'NeuroBEM: Hybrid Aerodynamic Quadrotor Model', RSS 2021 (arXiv:2106.08015), Section III-D, equations 5-19 (extracted from the paper PDF); confirmed as Agilicious ModelPropellerBEM per agilicious docs section 1.9 and readme ('optionally provides aerodynamic BEM models as described in Bauersfeld RSS 21').
- **Parameters:** Coefficients (c_l0, c_d0, theta0, theta1, chord, k_beta, e) are platform-specific thrust-stand fits; not published as plug-in defaults. Reported accuracy: >50% positional RMSE reduction in re-simulated trajectories vs state-of-the-art models.
- **Relevance:** The single biggest gap vs rotorpy's inventory. rotorpy approximates the same physics with separate additive/multiplicative corrections (H-force, blade-flapping moment, translational lift, AoA thrust correction, k_v2 climb term); BEM unifies them self-consistently and adds two effects genuinely absent: (a) induced-velocity solution coupling thrust to inflow, (b) vortex-ring-state descent behavior (eq 18-19). For the planned JAX port the inner fixed-point solve for v_i is differentiable via implicit differentiation, and closed-form azimuth integrals of eqs 13-15 exist (standard helicopter results) so the double integral need not be evaluated numerically.
- **Notes:** Adopt as an optional high-fidelity per-rotor model alongside the existing polynomial model, mirroring Agilicious's ModelRotorSimple / ModelRotorBEM toggle. The learned residual-network half of NeuroBEM (inputs: 20-sample / 2.5 ms history of linear+angular velocity and motor speeds, outputs f_res, tau_res) is data-driven, not first-principles — excluded from this recommendation. **SUPERSEDED 2026-08-19:** landed and PROMOTED via the executed agilib code — see "NeuroBEM / agilicious agilib (EXECUTED)" below, which also records where the executed code deviates from these paper equations (camber offset, H-force ×3.0, U_P sign, VRS blend).

### MuJoCo inertia-based fluid model (used by menagerie Skydio X2 and Crazyflie via option density/viscosity) — **ADOPTED (candidate tier)**

- **Equations:** Per body, in the BODY frame, with v and omega the body linear/angular velocity relative to the fluid (wind). Equivalent-box half-dimensions from the body's own inertia: r_x = sqrt(3 (I_yy + I_zz - I_xx) / (2 m)), cyclic for r_y, r_z. Quadratic (high-Re) terms: f_D,i = -2 rho r_j r_k |v_i| v_i (force, per axis i with j,k the other axes); g_D,i = -(1/2) rho r_i (r_j^4 + r_k^4) |omega_i| omega_i (torque). Viscous (low-Re, Stokes) terms with r_eq = (r_x + r_y + r_z)/3: f_V,i = -6 beta pi r_eq v_i; g_V,i = -8 beta pi r_eq^3 omega_i. rho = fluid density [kg/m^3], beta = dynamic viscosity [Pa*s].
- **Source:** MuJoCo documentation, Computation > Fluid forces (mujoco.readthedocs.io/en/stable/computation/fluid.html), inertia-based model section. Activated in google-deepmind/mujoco_menagerie skydio_x2/x2.xml via <option timestep="0.01" density="1.225" viscosity="1.8e-5"/> and bitcraze_crazyflie_2/cf2.xml via <option integrator="RK4" density="1.225" viscosity="1.8e-5"/> (neither file contains fluidshape/fluidcoef, so the ellipsoid model is NOT used).
- **Parameters:** rho = 1.225 kg/m^3, beta = 1.8e-5 Pa*s in both drone models; box dims derived automatically from each body's mass/inertia.
- **Relevance:** The translational quadratic term duplicates rotorpy's parasitic quadratic drag, and the linear Stokes force term duplicates the just-added differentiable linear drag. What rotorpy's inventory LACKS is any aerodynamic ANGULAR damping: the quadratic torque g_D,i = -(1/2) rho r_i (r_j^4 + r_k^4) |omega_i| omega_i and linear g_V,i = -8 beta pi r_eq^3 omega_i. A diag-coefficient rotational damping torque -diag(c_R) . (|omega| o omega) - diag(c_r) . omega is cheap, stabilizing for RL/optimization, JAX-trivial, and has this credible provenance.
- **Notes:** Physical honesty caveat: for a quadrotor most real rotational damping comes from the rotors (already captured by rotor drag with lever arms), so treat c_R, c_r as small fitted residual coefficients, not derived from the inertia-box formula.

### MuJoCo ellipsoid fluid model (added mass, Magnus, Kutta lift, angular drag) — *skipped*

- **Equations:** Per geom with fluidshape="ellipsoid", semi-axes r = (r_x, r_y, r_z), volume V = 4 pi r_x r_y r_z / 3, body frame, o = elementwise product. Added mass: f_A = -m_A o dv/dt + (m_A o v) x omega; g_A = -I_A o domega/dt + (m_A o v) x v + (I_A o omega) x omega, with m_A,i = rho V kappa_i / (2 - kappa_i) (kappa_i the standard potential-flow ellipsoid integral). ## Motor / ESC / battery first-principles literature

All four areas researched from primary sources with exact provenance. (1) DC motor model: the credible published quadrotor form is Bangura et al. ICRA 2014 eqs (11)-(15) -- v_a = Ke*W + i*Ra + La*di/dt, tau = (Kq0 - Kq1*i)*i, Ir*dW/dt = tau - (b1*W^2 + b2*W) -- with a full measured parameter table (Ra 0.07 Ohm, La 0.1 mH, Ir 5.38e-5 kg m^2, Kv 950); inductance is negligible (tau_e ~ 1.4 ms, authors neglect it), giving the quasi-static nonlinear speed ODE J*dW/dt = (Kq/Ra)(u*Vbatt - Ke*W) - km*W^2, which linearizes to the spec's existing tau_m lag with tau_m = J/(KqKe/Ra + b + 2*km*W0) and yields a closed-form battery-coupled steady state W_ss(u*Vbatt). (2) Bangura & Mahony's dynamic thrust: T = 2*rho*A*v_i*U, P_a = 2*rho*A*v_i*U*(v_i - Vz), U = sqrt(Vx^2+Vy^2+(v_i-Vz)^2), implicit v_i solve, coupled to the motor by P_m = P_a/FoM + Ir*W*dW/dt (FoM ~ 0.67 measured); this is the first-principles superset of the spec's existing empirical AoA/advance-ratio, climb, and translational-lift corrections and must replace rather than stack on them. (3) Batteries: verified the Chen & Rincon-Mora 2006 Thevenin ECM including all six fitted LiPo coefficient functions from the author-hosted PDF, and the actually-standard drone-sim model, Gazebo's LinearBatteryPlugin V = e0 + e1*(1 - q/c) - r*i_smooth (exact code); Tremblay-Dessaint and Peukert documented but recommended skip (redundant / wrong chemistry with contested exponent). (4) ESC: linear duty-to-mean-voltage confirmed from Crazyflie firmware comments; both Crazyflie compensation generations extracted verbatim with coefficients -- legacy quadratic (tag 2022.01 motors.c lines 152-173: v = -0.0006239*g^2 + 0.088*g, pwm = 65535*v/Vbatt) and current cubic thrust(v_motor) with Cardano inversion plus all three per-propeller coefficient sets from platform_defaults_cf2.h lines 57-91. Net recommendation: seven adopt-candidates that share one architecture -- voltage-input motor ODE + per-motor current draw -> load-dependent battery model -> V_batt feeds back into W_ss and firmware-style compensation -- replacing the spec's open-loop time-based sag and decoupled throttle curve; everything already in the verified inventory (first-order lag, exact-exp discretization, polynomial thrust maps, PWM quantization) was confirmed as the correct reduced form of these models, not contradicted.

### Quasi-static DC motor with quadratic aerodynamic load (nonlinear rotor-speed dynamics) — **ADOPTED (candidate tier)**

- **Equations:** Scalar dynamics about each rotor spin axis (body-fixed motor axis; SI units). Full model: L_a*di/dt = V_m - R_a*i - K_e*W ; J_r*dW/dt = K_q*i - tau_load(W), tau_load = k_m*W^2 (+ b*W viscous). Symbols: i = motor current [A], V_m = motor terminal voltage [V], R_a = winding resistance [Ohm], L_a = inductance [H], K_e = back-EMF constant [V*s/rad], K_q = torque constant [N*m/A] (K_q = K_e in consistent SI for an ideal machine), W = rotor angular speed [rad/s], J_r = rotor+prop inertia about spin axis [kg*m^2], k_m = aerodynamic torque coefficient [N*m*s^2/rad^2]. With inductance neglected (see separate finding), i = (V_m - K_e*W)/R_a and the speed dynamics become the scalar nonlinear ODE: J_r*dW/dt = (K_q/R_a)*(V_m - K_e*W) - k_m*W^2 - b*W. Published form (Bangura et al., ICRA 2014, eqs (11)-(15)): v_a = K_e*W + i_a*R_a + L_a*di_a/dt (11); tau = (K_q0 - K_q1*i_a)*i_a (12) [current-dependent torque constant K_q(i_a)=K_q0-K_q1*i_a, eq (14)]; I_r*dW/dt = tau - D_r (13); D_r = b1*W^2 + b2*W (15). Published static form (Bangura & Mahony, ACRA 2012, eqs (6a),(6b),(7)): V_ai = K_e*W_i + R_a*i_ai ; tau_zi = K_q*i_ai ; P_mi = (K_q*W_i/R_a)*(V_ai - K_e*W_i). Per-motor battery current draw for battery coupling: i_a = (V_m - K_e*W)/R_a, or equivalently i_ai = P_mi/(K_q*W_i) (ACRA 2012, Sec 3.5).
- **Source:** Bangura, Lim, Kim, Mahony, 'Aerodynamic Power Control for Multirotor Aerial Vehicles', ICRA 2014, eqs (11)-(15) and Table I (verified from ANU open-access PDF, https://openresearch-repository.anu.edu.au/bitstream/1885/11442/1/Bangura%20et%20al%20Aerodynamic%20power%20control%202014.pdf); Bangura & Mahony, 'Nonlinear Dynamic Modeling for High Performance Control of a Quadrotor', ACRA 2012, eqs (6a),(6b),(7) and Table 1 (verified from http://www.araa.asn.au/acra/acra2012/papers/pap121.pdf)
- **Parameters:** ICRA 2014 Table I (mid-size 14-pole BLDC, ~10 in prop class): R_a = 0.07 Ohm; L_a = 0.1 mH; K_e printed as '950 V/W' which is the motor Kv rating (950 RPM/V, i.e. K_e_SI = 60/(2*pi*950) = 0.01005 V*s/rad -- unit label in paper is ambiguous, flag when adopting); K_q0 = 0.0242 N*m/A; K_q1 = 0.0014 N*m/A^2; I_r = 5.3847e-5 kg*m^2; b1 = 2.9665e-9 (N*m*s^2/rad^2 implied); b2 = 5.5613e-6 (N*m*s/rad implied). ACRA 2012 Table 1 (smaller motor, ~5000 RPM hover, up to ~5 N/rotor): R_a = 0.5033 Ohm; K_q = 0.0099375 N*m/A; K_e = 0.0013 (units V/RPM most consistent with their 11.1 V supply: 0.0013 V/RPM = 0.0124 V*s/rad, close to K_q as SI theory demands; flag as inferred); C_T = 1.536e-7 N/RPM^2; thrust-to-torque tau = 0.012648*T (kappa = 79.066 1/m); FoM = 0.67483. Typical electrical time constant L_a/R_a = 1.4 ms.
- **Relevance:** This is the principled replacement for / superset of rotorpy's first-order lag + asymmetric quadratic spin-up/down model (multirotor.py lines 188-199): it adds physical voltage input (hence battery coupling), saturation asymmetry (accelerating torque bounded by (K_q/R_a)*(V_max - K_e*W), decelerating torque bounded by drag + braking), and per-motor current draw needed to close the loop with any load-dependent battery model. One extra state per rotor is avoided by noting W is already a state in rotorpy; only the RHS changes. Smooth algebraic RHS is JAX-friendly.
- **Notes:** The spec's existing quadratic asymmetric-lag model (Crazyflow-derived) is a phenomenological fit of exactly this ODE; adopting the physical form replaces 4 fit coefficients with (R_a, K_e, K_q, J_r, k_m) that are measurable and battery-voltage dependent. k_m can be reused from the existing per-rotor k_m torque polynomial (c2 term).

### Reduction of the DC-motor + quadratic-load model to a first-order speed lag (tau_m parameter bridge) — already covered

- **Equations:** Linearize J_r*dW/dt = (K_q/R_a)*(u*V_batt - K_e*W) - k_m*W^2 - b*W about operating speed W_0: d(dW)/dt = -(1/tau_m)*dW + (K_q/(R_a*J_r))*d(u*V_batt), with tau_m = J_r / (K_q*K_e/R_a + b + 2*k_m*W_0). Reduces to a pure first-order lag when (i) L_a/R_a << tau_m (always true, above), and (ii) operation stays near W_0 so the quadratic load is locally linear, or (iii) the ESC closes a high-gain speed loop, which Bangura & Mahony implement as v_a = v_ff(W_d) - K_W*(W - W_d) (IFAC 2014 eq (10)); the closed loop is then approximately first-order with bandwidth set by K_W (they report Motor/ESC response time 0.05 s at 1 kHz, Table 1 of IFAC paper). Symbols: u = ESC duty in [0,1], V_batt = bus voltage [V], W_d = commanded speed [rad/s], K_W = ESC feedback gain [V*s/rad]; others as above.
- **Source:** Derivation is standard linearization of Bangura ICRA 2014 eqs (11)-(15); ESC closed-loop justification and 0.05 s response time from Bangura & Mahony, 'Real-time Model Predictive Control for Quadrotors', IFAC World Congress 2014, eq (10) and Table 1 (verified from IFAC proceedings PDF, uamt.fei.stuba.sk mirror)
- **Parameters:** With ICRA 2014 values at W_0 ~ 500 rad/s: tau_m = J_r/(K_q*K_e/R_a + 2*k_m*W_0) is in the tens-of-ms range, consistent with rotorpy's tau_m defaults and the published 0.05 s response.
- **Relevance:** Confirms the spec's tau_m first-order lag and exact-exp discretization are the correct reduced model for speed-controlled ESCs; the bridge formula lets tau_m be computed from physical motor parameters instead of guessed, and predicts tau_m grows as battery sags (V_batt drops K_e*W headroom) and shrinks at higher trim speed.
- **Notes:** Worth keeping the bridge formula in docs even without new code: it links the identified tau_m to (J_r, R_a, K_e, K_q, k_m) for domain randomization in the planned JAX port.

### Static polynomial thrust/torque/power maps — already covered

- **Equations:** T = C_T*W^2, tau = C_Q*W^2, P = C_P*W^3 (ICRA 2014 eq (2)); IFAC 2014 uses T_i = C_T0*W + C_T*W^2 (eq (9)); mixer [T; tau_x; tau_y; tau_z] = M*[T1..T4] with kappa = thrust-to-torque ratio (IFAC eq (8)). W in rad/s or RPM per the fit; T [N], tau [N*m].
- **Source:** Bangura & Mahony IFAC 2014 eqs (8),(9); Bangura & Mahony ACRA 2012 Sec 3.2 (T = C_T*W^2, tau_z = C_Q*W^2, C_Q = C_T/kappa)
- **Parameters:** ACRA 2012: C_T = 1.536e-7 N/RPM^2 (R^2=0.997), tau = 0.012648*T i.e. kappa = 79.07 1/m, tau_z = 0.0099375*i_a N*m/A.
- **Relevance:** Duplicate of rotorpy's per-rotor c0+c1*W+c2*W^2 thrust/torque polynomials and per-rotor k_eta/k_m.
- **Notes:** Only new datum is a published kappa (thrust-to-torque, meters) magnitude for sanity-checking parameter files; cf. Crazyflie THRUST2TORQUE below.

### Momentum-theory dynamic thrust with induced-velocity solve (Bangura & Mahony) — **ADOPTED (candidate tier)**

- **Equations:** Per rotor, in the rotor hub / body frame {B} with z positive DOWN for vehicle velocity V and induced velocity v_i positive UP through the disc (sign convention stated explicitly in ACRA 2012 after eq (11)): T = 2*rho*A*v_i*U (ACRA eq (10a) / ICRA eq (3)); P_a = 2*rho*A*v_i*U*(v_i - V_z) (ACRA eq (10b) / ICRA eq (5)); U = sqrt(V_x^2 + V_y^2 + (v_i - V_z)^2) (ACRA eq (11) / ICRA eq (4)). Per-rotor airflow velocity includes the lever arm: V_i = V + Omega x r_i, r_i = rotor position offset (ACRA Sec 3.4). Hover limit (V=0): v_h = sqrt(T/(2*rho*A)) and P = T^(3/2)/sqrt(2*rho*A) (arXiv:1601.00733, eqs (4),(5) and Remark 4). Power bookkeeping coupling aero to the motor shaft: P_m = P_a/FoM + P_r, P_m = tau*W, P_r = I_r*W*dW/dt (ICRA 2014 eqs (6)-(10)); equivalently the aerodynamic load torque in the rotor-speed ODE is tau_a = P_a/(FoM*W). Given P_a (or motor power), v_i is found by Newton iteration on the implicit equations (ACRA Sec 3.4). Symbols: rho = air density [kg/m^3], A = pi*R^2 rotor disc area [m^2], V_x,V_y,V_z = rotor velocity relative to air in {B} [m/s], v_i = induced velocity [m/s], T [N], P_a = aerodynamic power [W], FoM = figure of merit [-], I_r [kg*m^2]. Validity caveat: momentum theory fails in descent between hover and windmill-brake state (vortex-ring / turbulent-wake states, descent rates between ~0.5*v_h and ~2*v_h; arXiv:1601.00733 Sec 2 discussion of VRS/TWS/WBS).
- **Source:** Bangura & Mahony, ACRA 2012, eqs (10a),(10b),(11), Sec 3.3-3.5; Bangura, Lim, Kim, Mahony, ICRA 2014, eqs (3)-(10); Bangura, Melega, Naldi, Mahony, 'Aerodynamics of Rotor Blades for Quadrotors', arXiv:1601.00733, eqs (1)-(5), (28),(29), Remark 4
- **Parameters:** FoM = 0.67483 measured (ACRA 2012 Table 1); FoM typically 0.6-0.7 for quadrotor rotors, theoretical max 0.81 (arXiv:1601.00733, p. following eq (8) citations to Leishman); rho = 1.225 kg/m^3 sea level.
- **Relevance:** First-principles replacement for rotorpy's stack of empirical airflow corrections: the multiplicative thrust vs AoA/advance-ratio correction, the k_v2*vz*|vz| climb term, and translational lift k_h*(vx^2+vy^2) are all low-order fits of exactly this T(V, W) surface. Combined with the motor ODE above it yields 'dynamic thrust': thrust responds correctly to climb/descent/translation and to battery-limited power without separate hand-tuned terms. The implicit v_i solve is a smooth scalar root-find per rotor (fixed-count Newton is differentiable, suits the JAX port).
- **Notes:** If adopted, it should replace (not stack on top of) the existing empirical thrust-correction terms to avoid double counting; keep the empirical path as the cheap option. Do not trust it in the VRS descent band; clamp or blend there.

### ESC averaged model: PWM duty -> mean motor voltage, and steady-state speed vs u*V_batt — **ADOPTED (candidate tier)**

- **Equations:** Averaged inverter model (standard, and exactly what Crazyflie firmware documents): V_m = u * V_batt, u = PWM/PWM_max in [0,1] (crazyflie-firmware platform_defaults_cf2.h line 58 comment: 'v_motor = v_battery * PWM / 65535.0'). Substituting into the quasi-static motor+load balance gives the battery-coupled steady-state speed: k_m*W_ss^2 + (K_q*K_e/R_a + b)*W_ss - (K_q/R_a)*u*V_batt = 0, so W_ss(u, V_batt) = [ -(K_q*K_e/R_a + b) + sqrt( (K_q*K_e/R_a + b)^2 + 4*k_m*(K_q/R_a)*u*V_batt ) ] / (2*k_m). Units: V_m, V_batt [V]; u dimensionless; W_ss [rad/s]; other symbols as in the motor finding. Behavior: W_ss is concave in u*V_batt, approximately proportional to sqrt(u*V_batt) when the quadratic load dominates and approximately linear in u*V_batt near zero load -- this is precisely the shape rotorpy's throttle curve W_c = (Wmax-Wmin)*sqrt(k*u^2 + (1-k)*u) + Wmin emulates.
- **Source:** Duty-to-voltage: bitcraze/crazyflie-firmware, src/platform/interface/platform_defaults_cf2.h line 58 (master, read 2026-08-10); steady-state expression derived from Bangura ICRA 2014 eqs (11)-(15) with dW/dt=0, di/dt=0 (standard algebra)
- **Parameters:** Using ICRA 2014 Table I values the formula reproduces realistic RPM-vs-voltage droop; K_q*K_e/R_a with K_e = 0.01005 V*s/rad, K_q ~ 0.01 N*m/A, R_a = 0.07 Ohm gives linear-drag-equivalent 1.4e-3 N*m*s/rad.
- **Relevance:** Gives the physically-correct coupling W_ss = f(u * V_batt) that the spec currently approximates with two decoupled pieces: the throttle shape curve and the battery-voltage speed cap. With this model a sagging battery lowers speed at every throttle, not just the clip ceiling, and the throttle curve emerges from (K_e,K_q,R_a,k_m) instead of a shape parameter.
- **Notes:** Closed-form, no iteration, differentiable everywhere for u*V_batt >= 0. Subsumes both the existing throttle-curve and battery-scale mechanisms when the cmd_motor_throttle abstraction is used.

### ESC inner-loop speed control (voltage feedforward + high-gain P feedback) — already covered

- **Equations:** v_a = v_ff(W_d) - K_W*(W - W_d) (IFAC 2014 eq (10)), where v_ff is the static voltage-vs-speed map from bench tests, W_d the commanded rotor speed [rad/s], K_W a proportional gain [V*s/rad]; runs at 1 kHz on the ESC; W_d obtained by inverting T_i = C_T0*W + C_T*W^2 (IFAC eq (9)).
- **Source:** Bangura & Mahony, IFAC World Congress 2014, eqs (9),(10), Table 1, Fig. 2
- **Parameters:** Motor/ESC loop: 1000 Hz, 0.05 s response time (IFAC 2014 Table 1).
- **Relevance:** This is why commanded-speed abstractions close to a first-order lag in practice; rotorpy's cmd_motor_speeds + tau_m already models exactly this closed loop.
- **Notes:** Only adopt if simulating ESC-firmware-level behavior (e.g., RPM-feedback ESCs vs open-loop duty ESCs as distinct actuator classes).

### Quadratic PWM-voltage map (ACRA 2012 ESC calibration) — *skipped*

- **Equations:** PWM_i = (V_ai / V_source)^2, PWM in fraction of cycle time (as printed in the paper). Contradicts the standard linear averaged model V = u*V_batt; specific to their ESC's throttle-to-duty firmware mapping, not inverter physics.
- **Source:** Bangura & Mahony, ACRA 2012, Sec 3.1 (unnumbered equation after eq (7))
- **Parameters:** none
- **Relevance:** Documents that hobby ESC throttle-input-to-duty maps can be nonlinear and vendor-specific; a simulator exposing a configurable throttle-map hook covers this. the spec's existing throttle curve already provides such a hook.
- **Notes:** Reported for completeness/skepticism: linear duty->voltage (Crazyflie comment) is the defensible default; treat any extra nonlinearity as a calibration curve, which rotorpy already supports.

### Crazyflie firmware battery-voltage thrust compensation -- legacy quadratic form — **ADOPTED (candidate tier)**

- **Equations:** Per motor, brushed CF2, executed before PWM output (firmware tag 2022.01, src/drivers/src/motors.c lines 152-173, read from raw.githubusercontent.com): if V_supply < 2.0 V: passthrough. Else: thrust_g = (ithrust/65536)*60 (ithrust = uint16 thrust command, thrust_g in grams over the fit domain 0-60 g); v_required = -0.0006239*thrust_g^2 + 0.088*thrust_g [V]; ratio = min(v_required / V_supply, 1); pwm_out = ratio * 65535. I.e. the firmware inverts a bench-fitted required-voltage-vs-thrust parabola and scales duty by 1/V_batt so mean motor voltage (u*V_batt) is held at v_required regardless of sag.
- **Source:** bitcraze/crazyflie-firmware, tag 2022.01, src/drivers/src/motors.c lines 152-173, function motorsCompensateBatteryVoltage (exact code fetched); background: Bitcraze 'PWM to Thrust' investigation page (bitcraze.io documentation, functional-areas/pwm-to-thrust)
- **Parameters:** coefficients -0.0006239 V/g^2 and 0.088 V/g; sanity cutoff 2.0 V; scale 60 g full range; RPM-to-thrust fit from same page: thrust_g = 1.0942e-7*rpm^2 - 2.1059e-4*rpm + 1.5417e-1 (grams vs RPM).
- **Relevance:** To simulate a stock Crazyflie faithfully (including its residual thrust error vs battery state), the sim must reproduce this firmware-side compensation between the controller's thrust command and the physical PWM, then apply the physical sag model. rotorpy has PWM quantization and a battery ceiling scale but no model of firmware compensation; without it, sim-real thrust mismatch appears as soon as V_batt deviates from the value the thrust map was identified at.
- **Notes:** Compensation is a compile-time option (CONFIG_ENABLE_THRUST_BAT_COMPENSATED); both compensated and uncompensated paths exist in fleets. Model it as an optional command-side transform, mirroring how motor_delay is handled.

### Crazyflie firmware battery compensation -- current cubic voltage-to-thrust model with Cardano inversion — **ADOPTED (candidate tier)**

- **Equations:** Static per-motor model (master firmware): v_motor = V_batt * PWM/65535 [V]; thrust_N(v_motor) = C0 + C1*v_motor + C2*v_motor^2 + C3*v_motor^3 [N per motor] (platform_defaults_cf2.h lines 57-62). Compensation (motors.c, function motorsCompensateBatteryVoltage, master): thrust = (ithrust/65535)*THRUST_MAX; if V_supply < 2.0 return 0; if thrust < THRUST_MIN return 0; else solve the cubic for the required motor voltage via Cardano: p = -C2/(3*C3); r = C1/(3*C3); q = p^3 + (C2*C1 - 3*C3*(C0 - thrust))/(6*C3^2); qrp = sqrt(q^2 + (r - p^2)^3); v_required = cbrt(q + qrp) + cbrt(q - qrp) + p; pwm_out = 65535 * v_required/V_supply. Torque model: torque = THRUST2TORQUE * thrust [N*m], THRUST2TORQUE in meters.
- **Source:** bitcraze/crazyflie-firmware master (read 2026-08-10): src/drivers/src/motors.c function motorsCompensateBatteryVoltage (exact code fetched via raw.githubusercontent.com); src/platform/interface/platform_defaults_cf2.h lines 57-91 (exact defines fetched); explanatory blog: bitcraze.io 2025/10 'Keeping Thrust Consistent as the Battery Drains'
- **Parameters:** CF2 with 2.1+ propellers (default): C0 = -0.02476537915958403, C1 = 0.06523793527519485, C2 = -0.026792504967750107, C3 = 0.006776789303971145 (N per motor vs V); THRUST_MIN = 0.012817578393224994 N, THRUST_MAX = 0.12 N per motor; THRUST2TORQUE = 0.0069928948992470565 m. Thrust upgrade kit: C0 = 0.006728127583707208, C1 = 0.01011557616217668, C2 = 0.010263198062061085, C3 = 0.0028358638322392503; THRUST_MIN = 0.01922636758983749 N, THRUST_MAX = 0.18 N; THRUST2TORQUE = 0.0051648627905205285 m. Legacy propellers: C0 = -0.014830744918356092, C1 = 0.04724465241828281, C2 = -0.01847364358025878, C3 = 0.005960923942142; THRUST_MAX = 0.12 N; THRUST2TORQUE = 0.007350862856566459 m.
- **Relevance:** Two distinct useful pieces for the simulator: (a) the forward cubic thrust_N(u*V_batt) is a bench-identified static actuator model tying thrust directly to duty and battery voltage for the CF2 -- an alternative parameterization of the ESC/motor steady state that slots into the cmd_motor_throttle path and makes the battery models in battery.py act on thrust correctly (rotorpy's VoltageBatterySag affine V->RPM map covers only the ceiling); (b) the inverse (Cardano) is the firmware behavior to emulate for closed-loop CF simulation. Values are per-motor, Newtons, volts -- directly usable in crazyflie_params.py.
- **Notes:** Note the master function returns 0 (motor off) below THRUST_MIN or V_supply < 2 V -- a discontinuity worth replicating exactly if emulating firmware, but to be smoothed/guarded in a differentiable JAX path. THRUST2TORQUE gives an independent published check on the CF k_m/k_eta ratio.

### Thevenin equivalent-circuit battery model (OCV-SoC + series R + RC transients), Chen & Rincon-Mora — **ADOPTED (candidate tier)**

- **Equations:** Cell-level, all SI; SOC in [0,1]. Charge state: C_capacity = 3600 * Capacity_Ah * f1(cycle) * f2(temp) [Farad-equivalent coulomb store] (paper eq (1)); dSOC/dt = -i_batt / C_capacity (discharge positive). Terminal voltage: V_batt = V_OC(SOC) - i_batt*R_Series(SOC) - V_TS - V_TL, with two RC branches: dV_TS/dt = -V_TS/(R_TS*C_TS) + i_batt/C_TS; dV_TL/dt = -V_TL/(R_TL*C_TL) + i_batt/C_TL. Fitted single-cell Li-polymer functions (paper eqs (2)-(7), 850 mAh TCL PL-383562 cell, all verified against the author-hosted PDF): V_OC(SOC) = -1.031*exp(-35*SOC) + 3.685 + 0.2156*SOC - 0.1178*SOC^2 + 0.3201*SOC^3 [V]; R_Series(SOC) = 0.1562*exp(-24.37*SOC) + 0.07446 [Ohm]; R_TS(SOC) = 0.3208*exp(-29.14*SOC) + 0.04669 [Ohm]; C_TS(SOC) = -752.9*exp(-13.51*SOC) + 703.6 [F]; R_TL(SOC) = 6.603*exp(-155.2*SOC) + 0.04984 [Ohm]; C_TL(SOC) = -6056*exp(-27.12*SOC) + 4475 [F]. For an nS pack: V_pack = n_series * V_cell, i_cell = i_pack (per parallel string). Load coupling: i_batt = sum over motors of i_a,i + i_avionics, with i_a,i from the motor model (i_a = (u*V_batt - K_e*W)/R_a).
- **Source:** M. Chen and G.A. Rincon-Mora, 'Accurate Electrical Battery Model Capable of Predicting Runtime and I-V Performance', IEEE Transactions on Energy Conversion 21(2):504-511, 2006, eqs (1)-(7) (verified from author-hosted PDF rincon-mora.gatech.edu/publicat/jrnls/tec05_batt_mdl.pdf)
- **Parameters:** As listed in equations field (single 850 mAh LiPo cell); pack scaling by n_series; coefficients must be re-fit per pack chemistry/size for quantitative work, functional form transfers.
- **Relevance:** This is the standard citable ECM for the exact phenomenon the spec's open-loop battery-sag terms currently fake: with it, voltage sag becomes load-dependent (aggressive flight sags more), SoC depends on actual current drawn, and the sharp knee below ~10% SOC emerges from V_OC(SOC). Feeding V_batt into the W_ss(u*V_batt) coupling or the Crazyflie cubic closes the loop the SkyDreamer observation motivated. All-smooth exponentials/polynomials: trivially JAX-portable; adds 3 scalar states total (SOC, V_TS, V_TL).
- **Notes:** Existing rotorpy battery.py covers only time-scheduled sag (no load dependence) -- this supersedes it while keeping the same update(t)->scale hook if the scale is computed from simulated V_batt. One RC branch (drop the long one) is usually sufficient at flight timescales, matching the V = V_oc(SoC) - R_int*i - V_RC form in the task brief.

### Linear battery model with internal resistance (Gazebo LinearBatteryPlugin) -- the de-facto drone-sim standard — **ADOPTED (candidate tier)**

- **Equations:** V = e0 + e1*(1 - q/c) - r*i_smooth (exact code line, gz-sim LinearBatteryPlugin.cc); q_dot: q = q - (dt * i_smooth)/3600 (q, c in Ah; i in A; dt in s); current low-pass: i_smooth += k*(i_raw - i_smooth), k = dt/tau. Symbols: e0 = OCV at full charge [V], e1 = (negative) linear OCV slope coefficient [V] applied over depth-of-discharge (1 - q/c), c = capacity [Ah], q = remaining charge [Ah], r = internal resistance [Ohm], tau = current filter time constant [s]. Note: this is the Thevenin model with affine V_OC(SoC) and the RC branch replaced by low-pass filtering the current.
- **Source:** gazebosim/gz-sim, branch gz-sim9, src/systems/battery_plugin/LinearBatteryPlugin.cc (voltage update, charge integration, and smoothing code lines fetched from raw.githubusercontent.com, 2026-08-10)
- **Parameters:** Model-file supplied per vehicle (e0, e1, c, r, tau); no universal defaults.
- **Relevance:** Documents what 'standard for drone sim' actually is: PX4/Gazebo-ecosystem vehicles use this affine-OCV + IR-drop model, not full ECMs. It is the minimal load-dependent upgrade to rotorpy's battery.py: two parameters more than LinearBatterySag, gives current-dependent sag and SoC bookkeeping, degenerate case of the Chen model.
- **Notes:** If the Chen ECM is adopted with configurable branches, this is its 0-RC affine special case -- implement one class with fidelity switches rather than two models.

### Tremblay-Dessaint generic battery model (MATLAB/Simulink) — *skipped*

- **Equations:** Li-ion discharge: V_batt = E0 - K*(Q/(Q - it))*i_star - K*(Q/(Q - it))*it + A*exp(-B*it) - R*i. Symbols: E0 = constant voltage [V], K = polarization constant [V/Ah or Ohm], Q = max capacity [Ah], it = integral of current (extracted charge) [Ah], i_star = low-pass-filtered current [A], A = exponential-zone amplitude [V], B = inverse exponential-zone time constant [1/Ah], R = internal resistance [Ohm]. Parameters extractable from 3 points of a datasheet discharge curve.
- **Source:** O. Tremblay, L.-A. Dessaint, 'Experimental Validation of a Battery Dynamic Model for EV Applications', World Electric Vehicle Journal 3(2):289-298, 2009 (equation form cross-checked via MathWorks Battery block doc and the WEVJ paper listing)
- **Parameters:** Vehicle-specific; extraction recipe: 3 points (full voltage, end of exponential zone, end of nominal zone) from manufacturer discharge curve.
- **Relevance:** Functionally redundant with the Chen ECM for rotorpy's purposes; its one advantage (datasheet-only fitting) matters more for EV packs than for drone LiPos, which are cheap to characterize by logging a flight.
- **Notes:** If a datasheet-only path is ever wanted, this is the credible reference; do not implement alongside the ECM -- pick one.

### Peukert capacity correction — *skipped*

- **Equations:** Discharge time t = H * (C/(I*H))^k, equivalently effective capacity C_eff = C*(C/(I*H))^(k-1); C = rated capacity [Ah] at rated discharge time H [h], I = actual discharge current [A], k = Peukert exponent [-].
- **Source:** L.W. Traub, 'Range and Endurance Estimates for Battery-Powered Aircraft', Journal of Aircraft 48(2):703-707, 2011 (applies Peukert-corrected endurance to LiPo-powered aircraft)
- **Parameters:** Traub adopts k ~ 1.3 for LiPo from prior literature; follow-up validation work ('Validation of endurance estimates for battery powered UAVs') and general LiPo data put k near 1.0-1.05 for healthy modern cells at moderate C-rates -- the exponent is contested for exactly the chemistry drones use.
- **Relevance:** Peukert was derived for lead-acid constant-current discharge; for high-C LiPo the dominant observable (voltage sag under load, knee near empty) is already captured by the IR/ECM models, and the parameter value for LiPo is disputed. Adds an endurance-prediction refinement, not a flight-dynamics effect.
- **Notes:** Reconsider only if the simulator's job expands to endurance/mission-energy prediction rather than flight dynamics and control.

### Aerodynamic power / FoM bookkeeping for thrust estimation (electrical-side observer) — already covered

- **Equations:** P_e = v_a*i_a [W] electrical; resistive loss i_a^2*R_a; mechanical P_m = tau*W = K_q(i_a)*i_a*W; rotor kinetic term P_r = I_r*W*dW/dt; aerodynamic P_a = FoM*(P_m - P_r) with FoM in [0,1] (ICRA 2014 eqs (6)-(10), eq (8): P_m = P_a/FoM + P_r). Enables estimating T from (v_a, i_a, W) without thrust sensing, via the momentum-theory P_a-T relation.
- **Source:** Bangura, Lim, Kim, Mahony, ICRA 2014, eqs (6)-(10) and Sec III; Bangura & Mahony, 'Thrust Control for Multirotor Aerial Vehicles', IEEE T-RO 33(2):390-405, 2017 (same architecture, per abstract/IEEE listing -- full text paywalled, equations not independently verified from T-RO version)
- **Parameters:** FoM = 0.67483 (ACRA 2012 Table 1); FoM 0.6-0.7 typical (arXiv:1601.00733).
- **Relevance:** Mainly an estimation/control architecture rather than a plant model; the plant-side content (motor ODE + momentum thrust) is already captured in the two adopt-candidates above. Could later support simulating RPM/power-telemetry ESCs.
- **Notes:** Marked already-covered in the sense that adopting findings 1 and 5 reproduces every plant equation here; nothing additional to implement on the dynamics side.


## Atmospheric turbulence standards (MIL-F-8785C / MIL-HDBK-1797)

Standard atmospheric turbulence for a small-multirotor simulator is fully specified by four published pieces, all now documented with exact equations: (1) Dryden PSDs/forming filters in both MIL-F-8785C and MIL-HDBK-1797 conventions (u-axis first-order, v/w second-order with a sqrt(3) zero), (2) the low-altitude (h < 1000 ft) closures L_w = h, L_u = L_v = h/(0.177+0.000823h)^1.2 (h in ft), sigma_w = 0.1*W20, sigma_u,v = sigma_w/(0.177+0.000823h)^0.4, (3) von Karman as the measurement-preferred alternative (irrational 5/6 and 11/6 exponents, realized via the standard rational approximation; low priority at multirotor bandwidths), and (4) the deterministic 1-cosine discrete gust V_m/2*(1-cos(pi*x/d_m)) for repeatable disturbance-rejection tests. The 'wind-dynamics' package is not on PyPI; it is goromal/wind-dynamics on GitHub (C++/pybind), and rotorpy vendors a faithful Python port at rotorpy/wind/dryden_utils.py. It implements the MIL-HDBK-1797 v/w filter (Tustin-discretized, correctly) but deviates from spec in five identified ways: v/w filter used on the u axis, 8785C length scales plugged into the 2L-convention filter (effective L doubled), driving noise Uniform(-1,1) without sqrt(pi/dt) scaling (empirically confirmed: gust RMS = sigma*sqrt(dt/(3pi)), i.e. dt-dependent and about 1.5% of nominal sigma at rotorpy's dt = 1/500), V frozen at 1 m/s (a defensible hover adaptation), and sigma unanchored to W20. Airspeed superposition v_a^B = R^T(v - W) is already correctly implemented (multirotor.py:478). Adopt-candidates: correct per-axis filters, sigma(W20,h) calibration, N(0, pi/dt) driving noise, 1-cosine gust; von Karman optional; angular-rate gusts skip. Also found: duplicate class DrydenGustLP definition in dryden_winds.py (line 111 shadows line 71).

### Dryden continuous-turbulence velocity PSDs (MIL-F-8785C / MIL-HDBK-1797) — already covered

- **Equations:** One-sided PSDs in spatial frequency Omega (rad/ft or rad/m), normalized so integral_0^inf Phi(Omega) dOmega = sigma^2. Taylor frozen-field hypothesis converts to temporal frequency: omega = V*Omega, Phi(omega) = Phi(Omega)/V, where V = vehicle true airspeed (ft/s or m/s). Components u,v,w = gust velocities along BODY axes (u longitudinal, along the relative-wind/mean-airspeed direction; v lateral; w vertical), units ft/s or m/s. MIL-F-8785C form: Phi_u(Omega) = sigma_u^2*(2*L_u/pi) * 1/[1+(L_u*Omega)^2]; Phi_v(Omega) = sigma_v^2*(L_v/pi) * [1+3*(L_v*Omega)^2]/[1+(L_v*Omega)^2]^2; Phi_w(Omega) = sigma_w^2*(L_w/pi) * [1+3*(L_w*Omega)^2]/[1+(L_w*Omega)^2]^2. MIL-HDBK-1797 form (length scales defined half as large, L_1797 = L_8785C/2 for v,w; identical spectra): Phi_u(Omega) = sigma_u^2*(2*L_u/pi) * 1/[1+(L_u*Omega)^2]; Phi_v(Omega) = sigma_v^2*(2*L_v/pi) * [1+12*(L_v*Omega)^2]/[1+4*(L_v*Omega)^2]^2; Phi_w(Omega) = sigma_w^2*(2*L_w/pi) * [1+12*(L_w*Omega)^2]/[1+4*(L_w*Omega)^2]^2. Symbols: sigma_u,v,w = RMS turbulence intensities (ft/s or m/s); L_u,v,w = turbulence length scales (ft or m).
- **Source:** MIL-F-8785C (Flying Qualities of Piloted Airplanes, 5 Nov 1980), turbulence model paras 3.7.1-3.7.2; MIL-HDBK-1797. Cross-checked against MathWorks Aerospace Blockset 'Dryden Wind Turbulence Model (Continuous)' documentation (mathworks.com/help/aeroblks/drydenwindturbulencemodelcontinuous.html), which reproduces both spec forms.
- **Parameters:** sigma and L set by altitude/severity (see low-altitude finding). The two spec conventions differ only by the factor-2 redefinition of L_v, L_w.
- **Relevance:** This is the spectral definition underlying the Dryden gusts rotorpy already generates (inventory: 'Dryden turbulence (via wind-dynamics pkg)'). Documented here as the spec baseline the implementation should be audited against.
- **Notes:** The rotorpy/wind-dynamics implementation realizes the v/w-form spectrum on all three axes; see the audit finding for deviations.

### Dryden forming filters H_u(s), H_v(s), H_w(s) (white-noise shaping filters) — **ADOPTED (candidate tier)**

- **Equations:** Continuous filters that turn unit-PSD white noise eta(t) into gust velocities with the Dryden spectra; s = Laplace variable (rad/s); V = airspeed (m/s or ft/s), L in m or ft, sigma in m/s or ft/s; outputs are body-frame gust velocities. MIL-F-8785C form: H_u(s) = sigma_u*sqrt(2*L_u/(pi*V)) * 1/(1+(L_u/V)*s); H_v(s) = sigma_v*sqrt(L_v/(pi*V)) * (1+sqrt(3)*(L_v/V)*s)/(1+(L_v/V)*s)^2; H_w(s) = sigma_w*sqrt(L_w/(pi*V)) * (1+sqrt(3)*(L_w/V)*s)/(1+(L_w/V)*s)^2. MIL-HDBK-1797 form (equivalent with L_1797 = L_8785C/2): H_u(s) = sigma_u*sqrt(2*L_u/(pi*V)) * 1/(1+(L_u/V)*s); H_v(s) = sigma_v*sqrt(2*L_v/(pi*V)) * (1+2*sqrt(3)*(L_v/V)*s)/(1+(2*L_v/V)*s)^2; H_w(s) = sigma_w*sqrt(2*L_w/(pi*V)) * (1+2*sqrt(3)*(L_w/V)*s)/(1+(2*L_w/V)*s)^2. Note |1+j*sqrt(3)*L*omega/V|^2 = 1+3(L*omega/V)^2 recovers Phi_v exactly. Monic small-UAV form (Beard & McLain 2012, sec. 4.4, algebraically identical to 8785C): H_u(s) = sigma_u*sqrt(2*V/(pi*L_u)) * 1/(s+V/L_u); H_v(s) = sigma_v*sqrt(3*V/(pi*L_v)) * (s+V/(sqrt(3)*L_v))/(s+V/L_v)^2; H_w analogous.
- **Source:** MIL-F-8785C / MIL-HDBK-1797 via MathWorks Dryden (Continuous) block doc; Beard & McLain, 'Small Unmanned Aircraft: Theory and Practice', Princeton Univ. Press, 2012, ch. 4.4 (monic form verified algebraically identical to the 8785C form). Implementation audited at rotorpy/wind/dryden_utils.py lines 22-29.
- **Parameters:** u-axis filter is FIRST order; v,w filters are second order with one zero.
- **Relevance:** Correction to the existing implementation: rotorpy's vendored filter applies the SECOND-order v/w filter shape to all three axes including longitudinal u (dryden_utils.py:22-29 builds H(s)=sigma*sqrt(2L/(pi*V))*(1+2*sqrt(3)*(L/V)s)/(1+(2L/V)s)^2 for every axis). Per spec, u must use the first-order filter. For a JAX rewrite, implementing the three distinct spec filters is a one-line-per-axis change with published provenance.
- **Notes:** Some printings of Beard & McLain drop the pi in the gain (known erratum); the forms above with pi are the spec-consistent ones.

### Low-altitude (h < 1000 ft) Dryden length scales and intensities vs altitude h and W20 — **ADOPTED (candidate tier)**

- **Equations:** Valid 10 ft < h < 1000 ft AGL, h in FEET. MIL-F-8785C: L_w = h; L_u = L_v = h/(0.177+0.000823*h)^1.2 (ft). MIL-HDBK-1797: 2*L_w = h; L_u = 2*L_v = h/(0.177+0.000823*h)^1.2. Intensities: sigma_w = 0.1*W20; sigma_u/sigma_w = sigma_v/sigma_w = 1/(0.177+0.000823*h)^0.4, where W20 = mean wind speed measured at 20 ft (6 m) AGL, same units as sigma (ft/s, kt, or m/s consistently). Severity anchors: light W20 = 15 kt (7.7 m/s), moderate W20 = 30 kt (15.4 m/s), severe W20 = 45 kt (23.2 m/s). Medium/high altitude (h >= 2000 ft): L_u = L_v = L_w = 1750 ft (8785C convention; 1797: L_u = 2L_v = 2L_w = 1750 ft), sigma from the spec exceedance-probability chart; 1000-2000 ft: linear interpolation of both L and sigma.
- **Source:** MIL-F-8785C paras 3.7.3.1/3.7.4 (low-altitude model); MIL-HDBK-1797; reproduced in MathWorks Dryden (Continuous) block doc. rotorpy length-scale code: rotorpy/wind/dryden_utils.py lines 131-133 (Lz_ft = 3.281*altitude; Lx_ft = Lz_ft/(0.177+0.000823*Lz_ft)^1.2; Ly_ft = Lx_ft).
- **Parameters:** Only two user inputs needed for a spec-consistent low-altitude model: h (ft) and W20. Beard & McLain Table 4.1 gives small-UAV metric presets (from memory, exact digits not re-verified online: at h = 50 m: L_u = L_v = 200 m, L_w = 50 m; light sigma_u = sigma_v = 1.06 m/s, sigma_w = 0.7 m/s; moderate sigma_u = sigma_v = 2.12 m/s, sigma_w = 1.4 m/s).
- **Relevance:** rotorpy implements the L(h) formulas (8785C convention) but NOT the sigma(W20,h) intensity model - sigma is a free user input with no physical anchor, and the default altitude 2.0 m (6.6 ft) sits below the 10-1000 ft fit range. Adopting sigma_w = 0.1*W20 and the ratio formula gives physically calibrated turbulence from a single measurable parameter (W20), which is exactly what a small-multirotor simulator wants.
- **Notes:** Deviation found: dryden_utils.py plugs 8785C-convention scales (L_w = h, L_u = L_v = h/(...)^1.2) into the 1797-convention (2L) filter form, making every effective length scale 2x the spec value. Beard & McLain table digits should be re-verified against the book before hard-coding (public mavsim repo has the values blanked as student TODOs).

### Discrete-time realization: Tustin discretization + driving-noise variance pi/dt — **ADOPTED (candidate tier)**

- **Equations:** Any Dryden filter written as H(s) = (alpha + beta*s)/(gamma*s^2 + delta*s + 1) discretized by the bilinear (Tustin) map s <- (2/dt)*(1-z^-1)/(1+z^-1) gives the difference equation y_k = [C4*u_k + C5*u_{k-1} + C6*u_{k-2} - C2*y_{k-1} - C3*y_{k-2}]/C1 with C1 = 1+2*delta/dt+4*gamma/dt^2, C2 = 2-8*gamma/dt^2, C3 = 1-2*delta/dt+4*gamma/dt^2, C4 = alpha+2*beta/dt, C5 = 2*alpha, C6 = alpha-2*beta/dt (algebra verified; dt = step, s). For the 1797 H_v: alpha = sigma*sqrt(2L/(pi*V)), beta = alpha*2*sqrt(3)*L/V, gamma = (2L/V)^2, delta = 4L/V. NOISE SCALING (the part rotorpy is missing): for the published gains to yield output variance sigma^2, the driving samples must be i.i.d. Gaussian u_k ~ N(0, pi/dt) (equivalently unit-variance Gaussian scaled by sqrt(pi/dt)). Derivation: with input two-sided PSD S0 (convention sigma^2 = (1/2pi)*integral S(omega) domega), the u-filter gives sigma_out^2 = S0*sigma_u^2/pi, so S0 = pi is required; discrete i.i.d. noise of variance sn^2 at step dt has flat PSD S = sn^2*dt over the Nyquist band, hence sn^2 = pi/dt.
- **Source:** Noise scaling sqrt(pi/dt): MathWorks 'Dryden Wind Turbulence Model (Discrete)' implementation convention; derivation above is self-contained. Code audited: rotorpy/wind/dryden_utils.py lines 43-51 (Tustin coefficients C1-C6, matching upstream goromal/wind-dynamics include/wind-dynamics/dryden_model.h) and line 50 (np.random.uniform(-1,1) input).
- **Parameters:** Correct discrete driving noise: N(0, pi/dt). Current code: Uniform(-1,1), variance 1/3, no dt scaling -> output std = sigma*sqrt(dt/(3*pi)). Empirically verified on the vendored code (seed 0, 350k samples): dt = 0.05 s -> std 0.0718 (predicted 0.0728); dt = 0.002 s -> std 0.0144 (predicted 0.0146), for sigma = 1.
- **Relevance:** Calibration bug in the existing Dryden implementation: gust magnitude depends on the integration step and is only ~1.5% of nominal sigma at rotorpy's default dt = 1/500 s (so default sig_wind = [1,1,1] m/s produces ~0.015 m/s gusts). Replacing uniform input with N(0, pi/dt) Gaussian makes sigma a true m/s RMS intensity, independent of dt - essential for a JAX rewrite where dt may vary.
- **Notes:** The Tustin part of the vendored code is correct; only the input-noise distribution/scaling breaks the calibration. Also note dryden_utils.integrate() (lines 60-73) sub-steps at 0.05 s, further coupling variance to call pattern.

### von Karman turbulence spectra (alternative to Dryden) + rational approximation filters — **ADOPTED (candidate tier)**

- **Equations:** One-sided spatial PSDs, symbols as in the Dryden finding, a = 1.339 (von Karman constant). MIL-F-8785C form: Phi_u(Omega) = sigma_u^2*(2*L_u/pi) * 1/[1+(1.339*L_u*Omega)^2]^(5/6); Phi_v(Omega) = sigma_v^2*(L_v/pi) * [1+(8/3)*(1.339*L_v*Omega)^2]/[1+(1.339*L_v*Omega)^2]^(11/6); Phi_w(Omega) = sigma_w^2*(L_w/pi) * [1+(8/3)*(1.339*L_w*Omega)^2]/[1+(1.339*L_w*Omega)^2]^(11/6). MIL-HDBK-1797 form (2L convention): Phi_v(Omega) = sigma_v^2*(2*L_v/pi) * [1+(8/3)*(2.678*L_v*Omega)^2]/[1+(2.678*L_v*Omega)^2]^(11/6), similarly Phi_w; Phi_u identical to 8785C. Non-integer exponents 5/6, 11/6 make the exact spectral factor irrational (no finite state-space filter); standard rational approximations (MathWorks, 8785C convention): H_u(s) = sigma_u*sqrt(2*L_u/(pi*V)) * (1+0.25*(L_u/V)*s)/[1+1.357*(L_u/V)*s+0.1987*(L_u/V)^2*s^2]; H_v(s) = sigma_v*sqrt(L_v/(pi*V)) * (1+2.7478*(L_v/V)*s+0.3398*(L_v/V)^2*s^2)/[1+2.9958*(L_v/V)*s+1.9754*(L_v/V)^2*s^2+0.1539*(L_v/V)^3*s^3]; H_w(s) same as H_v with (L_w, sigma_w). High-altitude von Karman scales: L_u = L_v = L_w = 2500 ft (8785C convention); low-altitude scales same formulas as Dryden.
- **Source:** MIL-F-8785C / MIL-HDBK-1797 via MathWorks 'Von Karman Wind Turbulence Model (Continuous)' documentation (mathworks.com/help/aeroblks/vonkarmanwindturbulencemodelcontinuous.html); polynomial coefficients verified against that doc. Preference statement: MIL-STD-1797A designates the von Karman form as the preferred spectral shape because it reproduces the Kolmogorov -5/3 inertial-subrange slope of measured turbulence (Dryden rolls off as omega^-2); Dryden is retained because it is rational and exactly realizable.
- **Parameters:** a = 1.339; exponents 5/6 and 11/6; approximation polynomial coefficients {0.25, 1.357, 0.1987} (u) and {2.7478, 0.3398, 2.9958, 1.9754, 0.1539} (v,w).
- **Relevance:** Not in the inventory. Optional higher-fidelity alternative: at multirotor scales the practical difference from Dryden is small and confined to high frequencies, so this is low priority - adopt only if spectral fidelity above ~V/L rad/s matters (e.g., vibration/estimator studies). The rational approximations above drop into the same Tustin + sqrt(pi/dt)-noise machinery as Dryden.
- **Notes:** For certification-style analyses and h > 2000 ft, von Karman is the specified model; for a low-altitude small UAV, Dryden with correct calibration is the accepted default.

### Discrete '1-cosine' gust model — **ADOPTED (candidate tier)**

- **Equations:** MIL-F-8785C discrete gust, applied per axis (body frame): V_wind(x) = 0 for x < 0; V_wind(x) = (V_m/2)*(1 - cos(pi*x/d_m)) for 0 <= x <= d_m; V_wind(x) = V_m for x > d_m. Symbols: x = distance penetrated into the gust (m or ft), typically x = V*(t - t0) with V = airspeed and t0 = gust onset; d_m = gust length / gradient distance (m or ft); V_m = gust amplitude (m/s or ft/s). Each axis may carry independent (V_m, d_m). Certification variant (FAR/CS 25.341, ramp-hold not required): U(s) = (U_ds/2)*(1 - cos(pi*s/H)) for 0 <= s <= 2H, with s = penetration distance, H = gust gradient distance, U_ds = design gust velocity.
- **Source:** MIL-F-8785C (Nov 5, 1980) discrete gust model, para 3.7.3.2; reproduced in MathWorks 'Discrete Wind Gust Model' block documentation (mathworks.com/help/aeroblks/discretewindgustmodel.html).
- **Parameters:** V_m: choose consistent with turbulence severity (spec ties discrete-gust magnitudes to the sigma exceedance chart); d_m: sweep over vehicle-relevant lengths. Hover adaptation: x is ill-defined at V ~ 0, so parameterize in time: V_wind(t) = (V_m/2)*(1 - cos(pi*(t-t0)/T_m)) with gust rise time T_m (s).
- **Relevance:** Not in the inventory. Trivial to implement (deterministic, differentiable, JAX-friendly), and it is the standard repeatable test input for disturbance-rejection tuning and controller benchmarking - complements the stochastic Dryden model rather than replacing it.
- **Notes:** rotorpy's wind_profile interface (update(t, position) -> world-frame wind vector) accommodates this directly as a new profile class.

### Body-frame application of turbulence: airspeed superposition — already covered

- **Equations:** World-frame wind W^W = W_mean^W + w_gust^W (m/s). Body-frame airspeed vector: v_a^B = R^T * (v^W - W^W), where v^W = inertial velocity of the vehicle in world frame (m/s), R = body-to-world rotation matrix (from the attitude quaternion), superscripts W/B = world/body frame. ALL aerodynamic terms (parasitic drag, rotor-drag H-force, blade flapping, translational lift, thrust angle-of-attack corrections) are evaluated with v_a^B in place of ground velocity. Per-rotor local airspeed includes the rotational lever arm: v_local^B = v_a^B + omega^B x r_i^B, with omega^B = body angular velocity (rad/s) and r_i^B = rotor position (m).
- **Source:** Standard flight-dynamics practice (MIL-F-8785C turbulence is defined as additive gust velocity in body axes). rotorpy implementation: rotorpy/vehicles/multirotor.py line 454 (wind_velocity = state['wind'], world frame) and line 478 (body_airspeed_vector = R.T@(inertial_velocity - wind_velocity)); batched version lines 1374 and 1402.
- **Parameters:** None beyond the wind vector itself.
- **Relevance:** rotorpy already does exact airspeed superposition, and its rotor-drag/flapping/thrust-correction terms all consume the airspeed vector. Frame subtlety worth documenting in the spec: MIL turbulence u,v,w are formally body-axis quantities generated at airspeed V under the frozen-field hypothesis; at hover V -> 0 the temporal spectra degenerate (time constants L/V -> inf), which is why small-UAV implementations (goromal/wind-dynamics, rotorpy) freeze V = 1 m/s and treat the gust output as a world-frame wind added to the mean wind. That is a reasonable, but non-spec, adaptation and should be stated as such.
- **Notes:** If per-spec body-frame anisotropy is ever wanted at forward speed, generate u along the mean relative wind and rotate into world frame before superposition.

### Dryden angular-rate gust components p_g, q_g, r_g — *skipped*

- **Equations:** MIL-F-8785C adds rotational gusts from spatial gradients of the velocity field, e.g. Phi_p(omega) = (sigma_w^2/(V*L_w)) * 0.8*(pi*L_w/(4b))^(1/3) / [1+(4b*omega/(pi*V))^2], and q_g, r_g obtained by filtering w_g, v_g: H_q(s) = (s/V)/(1+(4b/(pi*V))*s) * H_w(s), H_r(s) = (s/V)/(1+(3b/(pi*V))*s) * H_v(s). Symbols: b = wingspan (ft), V = airspeed (ft/s), sigma_w, L_w as before; outputs in rad/s.
- **Source:** MIL-F-8785C / MIL-HDBK-1797 (reproduced in MathWorks Dryden Continuous block doc).
- **Parameters:** b ~ vehicle span; for a sub-metre multirotor the 4b/(pi*V) corner frequencies push the rotational gust energy far above the rigid-body bandwidth and amplitudes scale with b^(1/3)/V.
- **Relevance:** Derived for fixed-wing span-differential effects; for a small multirotor the equivalent physics (per-rotor gust differences across the airframe) is negligible at L >> vehicle size, and rotorpy already captures the dominant rotational aero coupling via per-rotor local airspeed (omega x r term). Not worth the added state.
- **Notes:** If ever needed, the honest multirotor analogue is sampling a spatially correlated field at each rotor position, not the fixed-wing gradient filters.

### MIL-F-8785C logarithmic wind shear ('Wind Shear Model' block) — **ADOPTED (candidate tier)**

- **Equations:** u_w(h) = W20 * ln(h/z0) / ln(20/z0), valid 3 ft < h < 1000 ft, h and z0 in FEET (imperial fit, same trap as the low-altitude turbulence closures). W20 = mean wind at 20 ft AGL; z0 = 0.15 ft (Category C landing phase) or 2.0 ft (all other phases). Wind direction constant with height; magnitude-only profile.
- **Source:** MIL-F-8785C para 3.7.3.3; reproduced in MathWorks 'Wind Shear Model' block documentation (mathworks.com/help/aeroblks/windshearmodel.html).
- **Parameters:** Same W20 severity anchor as the Dryden intensity closures (light 15 kt, moderate 30 kt, severe 45 kt) — adopting it keeps mean wind and turbulence intensity mutually calibrated from one measurable parameter.
- **Relevance:** The deterministic member of the 8785C wind triad (shear + turbulence + gust); was the one missing piece — the ledger already covers the other two. Spec: `spec.wind.log_wind_shear`, registry `wind_shear_log`.
- **Notes:** Superposes onto v_wind exactly like the turbulence outputs; enters dynamics only through airspeed.

### Quaternion kinematics norm-drift correction ('6DOF (Quaternion)' block) — **ADOPTED (candidate tier)**

- **Equations:** qdot = (1/2)*Omega(omega)*q + K*eps*q with eps = 1 − (q_w^2+q_x^2+q_y^2+q_z^2), K >= 0 a normalization gain (1/s). The Omega term is norm-orthogonal, so d(||q||^2)/dt = 2*K*eps*||q||^2: norm error decays exponentially (rate ~2K near the unit manifold) instead of drifting under integration error. Identical to the verified kinematics on ||q|| = 1.
- **Source:** MathWorks '6DOF (Quaternion)' block documentation (mathworks.com/help/aeroblks/6dofquaternion.html), which prints the exact form; textbook basis Stevens & Lewis, *Aircraft Control and Simulation*; Zipfel, *Modeling and Simulation of Aerospace Vehicle Dynamics* (standard flight-simulation practice, Lagrange-multiplier style constraint stabilization).
- **Parameters:** K free; choose K*dt << 1 so the correction does not dominate the step.
- **Relevance:** The registry pushed renormalization to the harness (post-step projection). This is the smooth in-ODE alternative: one differentiable vector field, no projection kink — directly useful for the planned fully differentiable dynamics/JAX backend. Spec: `spec.quaternion.kinematics_norm_corrected`, registry `quaternion_norm_correction`.
- **Notes:** Post-step renormalization remains the default for non-differentiable paths; do not stack both corrections in one integrator.

### Atmosphere blocks: ISA / Lapse Rate / COESA / Pressure Altitude — already covered

- **Equations:** All four implement U.S. Standard Atmosphere 1976 (ISA per ISO 2533 is identical below 32 km; MathWorks cites only USSA-1976 even for its 'ISA' blocks). Lapse Rate page prints the exact troposphere/stratosphere forms already in `spec.atmosphere` (`isa_atmosphere` candidate). Pressure Altitude is the COESA pressure profile inverted.
- **Source:** mathworks.com/help/aeroblks/{isaatmospheremodel,lapseratemodel,coesaatmospheremodel,pressurealtitude}.html; USSA-1976 (NASA-TM-X-74335).
- **Notes:** The ISA block also offers Sutherland's-law viscosity mu = beta*T^(3/2)/(T+S) — not adopted; nothing in the catalog is Reynolds-dependent. Revisit only if a blade-element model with Re-dependent polars lands.

### Turbulence blocks: Dryden (Continuous/Discrete), Von Karman, Discrete Wind Gust — already covered

- **Equations:** Identical MIL-F-8785C / MIL-HDBK-1797 material already documented in this ledger (section above) and in `spec.wind`; the ledger already cites these exact doc pages as cross-checks. The blocks additionally expose the MIL-HDBK-1797B (2012) convention variant — same physics, same 2L bookkeeping as 1797.
- **Source:** mathworks.com/help/aeroblks/{drydenwindturbulencemodelcontinuous,drydenwindturbulencemodeldiscrete,vonkarmanwindturbulencemodelcontinuous,discretewindgustmodel}.html.
- **Notes:** Useful find in the blocks' reference lists: **NASA CR-1998-206937** (Yeager, 'Implementation and Testing of Turbulence Models for the F18-HARV Simulation', 1998) — a public NASA report containing complete Dryden implementations with code listings and published run statistics. Since adopted as pinned-document golden check data under the archaic-source exception (2026-08-11) and used to promote `dryden_turbulence` to verified — see the CR-1998-206937 entry in the turbulence section above.

### 6DOF equations-of-motion blocks (Euler / Quaternion / Wind / ECEF / variable-mass variants) — already covered

- **Equations:** Textbook rigid-body dynamics (Stevens & Lewis; Zipfel): F_b = m*(dV_b/dt + omega x V_b), M_b = I*domega/dt + omega x (I*omega) with full symmetric inertia — equivalent to the verified `newton_euler` + `quaternion_kinematics` after frame conversion (their body frame is FRD/NED). The quaternion variant's norm-correction term is the one new piece — adopted separately above.
- **Notes:** ECEF (rotating round Earth, Coriolis/centripetal), wind-axes (alpha/beta states), and variable-mass variants are fixed-wing/launch-vehicle machinery — out of scope for a meters-AGL multirotor.

### Rotor block (BEMT, Prandtl tip loss, quasi-steady Prouty flapping; R2023a+) — *skipped*

- **Equations:** Momentum/blade-element annulus balance 4*F*lambda^2*r = (1/2)*sigma_s*cl_alpha*(theta(r)*r − lambda)*r solved iteratively per station; Prandtl tip loss F = (2/pi)*acos(exp(−f)), f = (Nb/2)*(1−r)/(r*phi); thrust/torque nondimensionalized helicopter-style (T = C_T*rho*pi*R^2*(Omega*R)^2); steady flap angles per Prouty ch. 7 tilt the thrust vector.
- **Source:** mathworks.com/help/aeroblks/rotor.html; Prouty, *Helicopter Performance, Stability, and Control*; Leishman; Johnson. Validated by MathWorks against NACA TN-626.
- **Relevance:** Overlaps existing candidates: static uniform-annulus inflow is WEAKER than `dynamic_inflow_lag`; the C_T/C_Q parameterization is the same physics as `advance_ratio_tables` in helicopter instead of propeller nondimensionalization; quasi-steady flapping is covered by the flapping candidates. NeuroBEM already holds the high-fidelity BEM slot.
- **Notes:** The Prandtl tip-loss factor is the one reusable ingredient (public, Leishman/Prouty) — fold it in if a per-element BEMT term ever lands; not worth a standalone term.

### UAV Toolbox guidance models (multirotor / fixed-wing) — *skipped*

- **Equations:** Multirotor: point-mass translation m*xdd = [0;0;m*g] + R*[0;0;−F_thrust] plus INDEPENDENT PD loops on roll/pitch (pdot = Kp*(phi_c − phi) − Kd*p), P loop on yaw rate, first-order thrust lag — a closed-loop autopilot abstraction, cited to Mellinger & Michael IJRR 2012. Fixed-wing: Beard & McLain ch. 9 coordinated-turn kinematic model.
- **Source:** mathworks.com/help/uav/ref/guidancemodel.html; multirotor/fixedwing objects idem.
- **Relevance:** Not physics: the plant is a strict subset of the verified tier (no rotor aero, no drag, no motor dynamics beyond thrust lag) and the PD gains are control — harness-side by this repo's rules. The reduced-model role is already filled by the verified `point_mass_surrogate` (flightning), which was actually designed for gradient quality.

### Gravity family (WGS84 Gravity, Spherical Harmonic EGM96/EGM2008, Zonal J2–J4, Centrifugal, geoidheight) — *skipped*

- **Source:** NIMA TR8350.2 (WGS84); Lemoine (EGM96); Pavlis (EGM2008); mathworks.com/help/aeroblks/wgs84gravitymodel.html and siblings.
- **Relevance:** Normal-gravity variation is ~0.5% equator-to-pole and ~3e-6 per 10 m altitude — orders below the identification noise of every coefficient in this catalog. Constant-g (parameter `grav`) is correct at multirotor scale. Orbit machinery, out of scope.

### Upper-atmosphere / geophysical field family (CIRA-86, NRLMSISE-00, HWM07/14, non-standard day MIL-STD-210C/310) — *skipped*

- **Source:** COSPAR CIRA-86 (NASA TM100697); NRL MSISE-00; NRL HWM07/HWM14 (Drob et al.); MIL-STD-210C / MIL-HDBK-310; mathworks.com/help/aeroblks/{cira86atmospheremodel,nrlmsise00atmospheremodel,horizontalwindmodel07,nonstandardday210c}.html.
- **Relevance:** Thermosphere/climatic-extreme models for altitudes and use cases far outside a small multirotor's envelope. Off-nominal density days are already handled structurally: scale rotor coefficients by rho/rho_ident with rho from measured T, P (`isa_atmosphere` notes).

### World Magnetic Model (WMM2000–WMM2025) / IGRF — *skipped (pointer)*

- **Source:** NOAA/NGA WMM, public coefficients, 5-year epochs (default WMM2025); mathworks.com/help/aeroblks/worldmagneticmodel.html; `wrldmagm`/`igrfmagm`.
- **Relevance:** `spec/sensors.py` holds only the IMU today — there is no magnetometer term for a field model to feed. ADOPT WHEN a magnetometer measurement model lands: WMM (or a constant local-field vector for indoor work) is the standard source of the reference field, and the coefficients are public.

### Geodetic transforms and flight-parameter utilities (LLA/ECEF, flat-Earth, TAS/CAS/EAS correction, dynamic pressure, Mach, alpha/beta, compressible-flow relations, second-order servo actuators, Turbofan Engine System) — *skipped*

- **Source:** WGS84 / ANSI/AIAA R-004-1992 (transforms); Lowry, Gracey NASA RP-1046 (airspeed); NACA Report 1135 (flow relations); Stevens & Lewis (aero forces/moments); mathworks.com/help/aeroblks/ various.
- **Relevance:** Frame-boundary machinery (this repo keeps converters at the boundaries — golden generators, future backends), fixed-wing utilities, or generic servo/turbofan models with no multirotor content. `alphabeta`-style incidence quantities already appear inside the AoA thrust terms where needed.


## Prior evaluations (2026-07, RotorPy cross-validation phase)

- **RotorPy (spencerfolk/rotorpy)** — reference implementation for the Svacha aero model
  (k_d/k_z H-force, k_flap flapping moment, k_h translational lift), parasitic drag,
  first-order motor lag, and the rigid-body core; golden vectors generated from
  upstream @ 9b760b8 (2026-04-22). Findings against its IMU (rotorpy/sensors/imu.py,
  unfixed upstream as of 2026-08-19):
  **F-1 (lever-arm frame mixing)** — the rotational contribution to the sensor-point
  acceleration crosses body-frame ω/ω̇ with a world-frame lever arm
  (`np.cross(w_WB, p_BS_W)`), correct only for p_BS = 0; the correct form builds
  α×r + ω×(ω×r) in the body frame and rotates once.
  **F-2 (gyro ignores mounting rotation)** — the gyro returns raw body rates; a mounted
  sensor must read R_BSᵀ·ω. **F-2b (batched sensor rotation)** — the batched path
  composes R_SB and R_BW element-wise instead of as a matrix product.
  The spec's imu term derives the corrected model from first principles (strapdown
  kinematics) and proves it against an independent closed-form reference
  (properties/test_sensors.py).
- **Crazyflow (learnsyslab/crazyflow; Synetic-Labs fork)** — golden source for polynomial
  curves, asymmetric motor, mixing-matrix moments, lumped linear drag, AND the gyroscopic
  term. History of finding F-3: the original code had the gyro roll-row sign flipped
  (confirmed against running code); **fixed upstream by PR learnsyslab/crazyflow#86
  (merged 2026-07-13)** with the correct `(+q·S, −p·S, ·)` form. An earlier revision of that
  PR flipped the pitch row instead — superseded before merge.
  Golden vectors include prop_inertia and must be generated from a checkout at/after the
  PR #86 merge. Remaining observation: `ang_vel2quat_dot` applies a scalar-first Ξ(ω) to
  xyzw-stored quaternions (vestigial — their integrator uses ang_vel; docstring forbids
  integrating quat_dot).
- **SkyDreamer (arXiv:2510.14783)** — golden source for the AoA/advance-ratio thrust model
  and linear rotor drag. Coefficients are mass-/inertia-normalized (finding F-4); moments are
  per-rotor identified k_p/k_q/k_r (not structural); quadratic drag is per-axis |v_k|·v_k.
- **rpg_flightning (ICRA 2025)** — source of the exact-exponential motor discretization,
  the point-mass surrogate model, and the surrogate-gradient scheme. Physically a subset of
